# 开发群聊文件工作流 v2

新建双席位开发群聊使用 v2。旧群聊和单席位模式保持原协议，避免把旧的 FAIL 合并文档误认为成功。

| 阶段 | 草稿 | 交付文件 | 下一步 |
|---|---|---|---|
| 讨论 | 无 | 无 | 用户输入任务，点开题 |
| 开题 | 开题报告.md | 已完成-开题报告.md | 自动派第一席位实现 |
| 施工 N | 实现手册-轮次N.md | 已完成-实现手册-轮次N.md | 自动派第二席位独立审查与合并 |
| 合并 N | 合并手册-轮次N.md | 需返工-合并手册-轮次N.md | 自动派第一席位施工 N+1 |
| 合并 N | 合并手册-轮次N.md | 已完成-合并手册-轮次N.md | 任务完成 |

任务目录仍是 `<Hub 数据目录>/task-docs/<meetingId>/`。草稿只表示未交付，不证明 Agent 此刻还在运行。
Hub 只认精确文件名和连续轮次，忽略正文、字符数、mtime、聊天裁决和回复是否结束；质量由 Agent 的真实验证与项目合并入口保证。
同一阶段存在多个状态文件、缺失前序或成功后仍有后续文件时，显示文件冲突并停止自动派工。

开题是输入快捷操作：追加可编辑提示词、仅选择第一席位；不发送、不创建阶段文件。重复点击替换已有预填块，保留块外的用户文字。
用户检查后按正常 Enter 发送。自动派工时同步选择当前执行席位；用户仍可手动改选下一条消息的收件人。

停止保存暂停意图并使用现有 ESC 中断通道，不清理文件或退出 CLI。晚到的交付不解除暂停。
输入“继续”“继续执行”等明确指令后，从文件状态接续；进度询问不解除暂停。没有额外的恢复或重发按钮。
普通消息和群聊会话状态与业务阶段解耦；只保留必要的派工去重、在途准备和暂停记录。
重启不重复派已发送的同一阶段；未交付的工作可通过“继续”接续。缺失运行时席位从其完整持久记录恢复，被明确移除的会话不复活。
CLI 自身的登录、启动确认和额度错误仍如实显示，不能用完成文件掩盖。

通用 prompt 在 `core/dev-file-workflow.js`；项目合同只保存环境、验证与合并入口。
AUTHOR 不自行合并；MERGER 独立亲验，并满足项目授权条件后执行真实合并，成功后才改名完成。
项目配置和现有合并脚本不因 prompt 精简而替换。

验证入口：

```text
node scripts/run_unit_tests.js
node tests/dev-file-workflow-i-e2e.js
node tests/dev-file-workflow-l-e2e.js
```

I 层是真实隔离 Electron/UI/IPC/文件系统，派发器使用受控 fixture。
L 层使用真实 CLI、独立 worktree、测试与本地临时远端，读取本机凭据到隔离 profile；退出后清除创建的凭据副本。
L 层默认 Codex 实现、Claude 合并。`HUB_FILEFLOW_TEST_REVIEWER=codex` 可明确指定独立 Codex 合并位；必须在报告里注明。
`HUB_FILEFLOW_RESUME_ROOT` 指向同一专属临时目录时可验证恢复；测试不会连接或修改生产 Hub。
