# 开发群聊文件工作流 v2

新建开发群聊默认选中开发场景和已有路径，至少两位成员：第一位实现、第二位独立验证与合并，其余成员参与讨论。前端和创建 IPC 均拒绝单人开发群聊，不再提供极简模板或“独立开工”按钮。

单人开发使用普通 session 输入框上方的“一键开工”。点击只追加完整可编辑提示词，保留需求与附件，不发送；重复点击不叠加已有预设、不覆盖用户修改。用户发送后授权当前任务的自主实现、验证、审阅和合并；后续消息不自动追加，既有项目审批限制仍须遵守。没有阶段、文件改名、固定任务记录或工作台 JSON 要求，复杂任务按需保存必要记录。群聊成员的 session 视图不显示这个按钮。

历史 `soloDevelopment: true` 的会话及任务文件原样保留，仍可通过普通消息接续，不迁移、不删除。历史单人自测仍不宣称独立审查。

双席位使用下面的文件交接协议。历史群聊和旧 `dev-task-solo` 配置保持原协议，避免把旧的 FAIL 合并文档误认为成功。创建页不再提供起手卡片。

| 阶段 | 草稿 | 交付文件 | 下一步 |
|---|---|---|---|
| 讨论 | 无 | 无 | 用户输入任务，点开题 |
| 开题 | 开题报告.md | 已完成-开题报告.md | 自动派实现 Agent |
| 施工 N | 实现手册-轮次N.md | 已完成-实现手册-轮次N.md | 自动派合并 Agent 独立审查与合并 |
| 合并 N | 合并手册-轮次N.md | 需返工-合并手册-轮次N.md | 自动派实现 Agent 施工 N+1 |
| 合并 N | 合并手册-轮次N.md | 已完成-合并手册-轮次N.md | 任务完成 |

任务目录仍是 `<Hub 数据目录>/task-docs/<meetingId>/`。草稿只表示未交付，不证明 Agent 此刻还在运行。
Hub 只认精确文件名和连续轮次，忽略正文、字符数、mtime、聊天裁决和回复是否结束；质量由 Agent 的真实验证与项目合并入口保证。
同一阶段存在多个状态文件、缺失前序或成功后仍有后续文件时，显示文件冲突并停止自动派工。

职责按 `serialWorkflow.steps` 中的稳定 memberId 绑定，提示词从 Hub 会话读取实际显示名，不硬编码 Codex 1/2，也不按数组位置猜名字。开题是输入快捷操作：追加可编辑提示词、选择绑定的实现 Agent；不发送、不创建阶段文件。重复点击替换已有预填块，保留块外的用户文字。
用户检查后按正常 Enter 发送。自动派工时同步选择当前执行席位；用户仍可手动改选下一条消息的收件人。

停止保存暂停意图并使用现有 ESC 中断通道，不清理文件或退出 CLI。晚到的交付不解除暂停。
输入“继续”“继续执行”等明确指令后解除暂停，原文发送给用户选择的成员，不追加恢复/阶段提示词、不改收件人。锁定当前阶段避免扫描器抢发；只有之后的文件交付才触发下一阶段。进度询问不解除暂停。没有额外的恢复或重发按钮，文件工作流也不运行延迟 Codex 提交巡检的自动重发。
普通消息和群聊会话状态与业务阶段解耦；只保留必要的派工去重、在途准备和暂停记录。
重启不重复派已发送的同一阶段；未交付的工作可通过“继续”接续。缺失运行时席位从其完整持久记录恢复，被明确移除的会话不复活。
CLI 自身的登录、启动确认和额度错误仍如实显示，不能用完成文件掩盖。

通用 prompt 在 `core/dev-file-workflow.js`；项目合同只保存环境、验证与合并入口。
完整协议只在每个实际 Agent 会话首次成功送达时注入；失败不记已送达，记录随群聊状态持久化。普通消息沿用群聊 delta，不逐轮重发文件规则。协议版本、项目或角色/名字变化时更新协议。
每个阶段提示词独立提供输入文件、准确草稿/完成/返工路径和保存回读、同目录原子改名、确认目标存在及草稿消失的动作，不再内嵌完整协议。普通“继续”依赖已有上下文，不由 Hub 恢复施工。
首次协议和阶段指令要求用大白话简短汇报关键进展、结果或阻碍，复杂内容必要时用 HTML；只记录变化与必要证据，避免聊天重复文件全文。开发群聊界面仅去掉进展正文行首的 `PLAN:` / `UPDATE:`，保留原始消息、用户文字和代码块。
AUTHOR 不自行合并；MERGER 独立亲验，并满足项目授权条件后执行真实合并，成功后才改名完成。
项目配置和现有合并脚本不因 prompt 精简而替换。

验证入口：

```text
node scripts/run_unit_tests.js
node tests/dev-file-workflow-i-e2e.js
node tests/dev-prep-controls-e2e.js --solo  # 验证拒绝新建单人开发群聊
node tests/e2e-one-click-start-cdp.js
node tests/dev-prep-controls-e2e.js --double-codex
node tests/dev-prompt-policy-e2e.js
node tests/dev-file-workflow-l-e2e.js
```

I 层是真实隔离 Electron/UI/IPC/文件系统，派发器使用受控 fixture。
`dev-prompt-policy-e2e` 使用真实 Hub 派发器、原生 App Server stdio fixture 和界面验证实际发送内容、动态姓名、首发持久记录、普通继续与进展显示；它不证明真实模型执行质量或实测 token 节省比例。
L 层使用真实 CLI、独立 worktree、测试与本地临时远端，读取本机凭据到隔离 profile；退出后清除创建的凭据副本。
L 层默认 Codex 实现、Claude 合并。`HUB_FILEFLOW_TEST_REVIEWER=codex` 可明确指定独立 Codex 合并位；必须在报告里注明。
`HUB_FILEFLOW_RESUME_ROOT` 指向同一专属临时目录时可验证恢复；测试不会连接或修改生产 Hub。
