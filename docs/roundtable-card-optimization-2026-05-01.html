优化 2流式预览净化 · 方案 B 升级版（三家全 JSONL）

问题

当前 preview 直接取 PTY ringBuffer 尾部 500 字符，剥 ANSI 后还残留 throbbing 状态行（thinking more with xhigh effort）、tool call 噪声、cursor 重绘碎片，体验很差。

核心调研结论

AI原生流式数据源粒度当前是否用上
Claude ~/.claude/projects/<slug>/<sid>.jsonl 块级（thinking/text/tool_use 各一行） ✗ 仅 Stop 时读，未做 tail
Gemini ~/.gemini/tmp/<hash>/chats/session-*.jsonl chunk 级（每行 type:"gemini"） ⚠ 已 tail 但仅用于 token 计数 + 完成判定
Codex ~/.codex/sessions/<date>/rollout-*.jsonl delta 级（agent_message_delta 事件） ✗ 协议存在但项目未监听
关键发现：实测 Claude transcript 文件是块级实时追加（同一 message_id 的 thinking/text/tool_use 块按时序异步落盘，间隔 100-2000ms），不是 Stop 后整块写。所以 Claude 完全可以 tail，而且能拿到独家的 type:"thinking" 块和结构化 tool_use 块——比 Gemini 更丰富。

新数据流

Claude TUI session ↓ 块级追加 ~/.claude/projects/.../sid.jsonl → ClaudeTap.JsonlTail.onLine() → 缓存 thinking/text/tool_use 块到 _streamingBuf[sid] ↓ Gemini TUI session ↓ chunk 追加 ~/.gemini/tmp/.../session-*.jsonl → GeminiTap.onLine()（已存在） → 缓存 type:"gemini" content 到 _streamingBuf[sid] ↓ Codex TUI session ↓ delta 追加 ~/.codex/sessions/.../rollout-*.jsonl → CodexTap.onLine()（新增 delta 分支） → 缓存 agent_message_delta.delta 到 _streamingBuf[sid] ↓ ┌──────────────────────────┐ │ transcriptTap.getStreamingText(sid) │ ← 新接口 └──────────────────────────┘ ↓ main.js _rtExtractStreamingText(sid, kind) if tap.getStreamingText(sid) → 直接用（纯净，无噪声） else 走 PTY + 简化过滤器（兜底，仅启动头几秒） ↓ IPC 'roundtable-partial-update' → renderer mc-preview

兜底策略（PTY fallback）

JSONL 文件可能在 session 启动后 1-3 秒才创建好（CLI 自己写）。这段窗口期 PTY 仍是唯一数据源。所以 main.js 的逻辑：
  1. 优先 tap.getStreamingText(sid) → 拿到非空字符串就用
  2. 否则降级走 PTY ringBuffer + 简化过滤器（只剥 ANSI + 反向扫掉 PowerShell 提示符 + spinner 字符）
  3. 过滤器规则比现在更轻（不需要再扒 throbbing 文案，因为 JSONL 一就绪就接管）

Codex Spike 验证

Codex 的 agent_message_delta 事件在 transcript-tap.js:401 注释里说"存在但当前未用"。落地前必须做 30 分钟 spike：跑一次 Codex turn → tail rollout-*.jsonl → 确认 delta 事件的 JSON schema（特别是 payload.delta 字段是否真存在、是否拼接出完整文本）。spike 失败则 Codex 暂仍走 PTY。

优化 4动态重排兜底 · 杜绝模块重叠

问题

当 shell 显示/隐藏、卡片高度变化、窗口 resize、历史面板展开时，xterm.js 的 fit() 没及时调用，cards-tab 高度撑爆 grid，会出现重叠或滚动条错位。

触发场景清单

场景当前症状修复后
窗口 resize（拖拽边）xterm 内容裁切，cards 内容溢出实时重排 + xterm.fit()
沉浸/调试模式切换未实现（新功能）240ms 动画 + 完成后 fit()
历史轮次面板展开/收起cards 区压缩但 preview 高度未跟随观察容器变化重算
preview 区 markdown 长度跳变card 高度抖动带动相邻 cardgrid min-height: 0 + 固定 row 高度
session 添加/移除 AIgrid 列数变化时旧 fit() 状态错乱列数变化时强制重 fit()
devtools 打开/关闭视口变化未触发window resize 同步 fit()

实现栈

主容器 #meeting-room-panel ↓ 注册 ResizeObserver → debounce 100ms ↓ _relayoutMeetingRoom() ├─ cards-strip: grid minmax(0, 1fr) 强制重算 ├─ 每个 xterm: fitAddon.fit() └─ historyPanel: 重算 max-height ↓ 布局稳定，无重叠

关键 CSS 防溢出三件套

.mr-ft-strip {
  display: grid;
  grid-template-columns: repeat(3, minmax(0, 1fr)); /* 防 grid item 溢出 */
  gap: 8px;
  min-height: 0;                                  /* 让 grid 在 flex parent 中可缩 */
}
.mr-ft {
  display: flex;
  flex-direction: column;
  overflow: hidden;                                /* preview 长内容不撑爆卡片 */
}
.mr-ft-preview {
  flex: 1;                                          /* 抢占 row1/row2 之外的全部空间 */
  overflow-y: hidden;
}
