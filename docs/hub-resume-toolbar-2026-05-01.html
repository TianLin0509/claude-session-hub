5. 关键 Bug 修复 · GLM/DeepSeek Resume 模型覆盖

用户实测复现：在 hub 里 resume 一个 GLM 会话后，模型被错误地变成 claude-opus-4-7，而非原来的 glm-4.6。

根因（session-manager.js:487-496 & :455-456）

// ✅ 创建时正常
cmd = ` claude --model ${opts.model || cv.GLM_MODEL} --permission-mode bypassPermissions`;

// ❌ resume 时丢失 --model
if (opts.resumeCCSessionId) {
  cmd = ` claude --resume ${opts.resumeCCSessionId} --permission-mode bypassPermissions`;
  //                                                  ↑ 漏！
}

Claude CLI 看不到 --model 时，回退到全局 ~/.claude/settings.json 默认（通常是 opus 4.7），覆盖原始 GLM 模型。

修复方案

  1. state.json 记录原模型：确认 sessions[].model 字段创建时被写入（已有 currentModel.id，需 verify）
  2. main.js resume IPC 透传（第 2155-2169 行）：从 meta.model 读出原模型 → 传 opts.model
  3. session-manager.js 两个分支补 --model：GLM (487-496) + DeepSeek (455-456) 的 resume 命令拼接补 --model ${opts.model || cv.<KIND>_MODEL}
  4. 保险：~/.claude-glm/settings.json & ~/.claude-deepseek/settings.json 初始化时写默认 model 字段（Level 2 fallback）

6. 数据流 · resume 命令完整链路

用户点击 ↻ 恢复 ▾ 中的 GLM
  ↓
renderer.js: invoke('create-session', 'glm-resume')
  ↓
main.js IPC handler:
  - 从 state.json sessions[] 找到最近一个 kind=glm 的 session
  - 读 meta.model（如 'glm-4.6'）
  - createSession('glm-resume', { model: meta.model, ... })
  ↓
session-manager.js: kind === 'glm-resume' 分支
  - cmd = ` claude --resume --model glm-4.6 --permission-mode bypassPermissions`
  - env: ANTHROPIC_BASE_URL=<GLM> ANTHROPIC_AUTH_TOKEN=<k> CLAUDE_CONFIG_DIR=~/.claude-glm
  ↓
PTY 启动 → claude CLI 看到 --resume 弹 picker
  ↓
用户在 PTY 内选会话 → claude 启动该会话 + 强制 model=glm-4.6 ✓
