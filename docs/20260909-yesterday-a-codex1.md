# 昨日之我：A 版搜索工作台

用户反馈最近七天筛选像没生效、排序难理解、反复提醒建索引，且结果缺少关联问答。本次采用已经选定的 A 方案：项目导航、结果列表、只读卡片预览。

## 已实现的契约

- 搜索默认范围始终为标题、用户提问、AI 答复；全部内容显式包括工具。支持中文单字、去重关键词、跨消息 AND、完整 ID 精确查询。
- 相关度按完整标题/ID、完整短语、同条消息、同轮问答、跨轮分散依次比较，再比较最短词距、字段、真实对话时间、稳定 ID。命中次数不累加抬升排名。
- 最近对话、最近命中、标题排序独立。时间范围默认为消息发生时间；纯标题仅在范围内有真实对话时保留。摘要更新时间不是对话时间。请求冻结时区及起止毫秒。
- 过滤条件在候选预算前执行。结果为 complete / partial / error；partial 含 continuationCursor，完成后的分页用 nextPageCursor。游标绑定查询与 SQLite 读快照，保留最多四份，闲置两分钟过期；错误须重新搜索，不能把部分结果当全集。
- FTS/CJK 由虚表驱动，rowid 直接约束虚表。短词按主键推进，避免每批重新排序全范围。CJK 辅助表未回填完时使用完整扫描；不以不完整辅助表换取速度。
- 每条会话展示最佳相关问答，卡片复用已有 Markdown/公式渲染，移除会话操作和 live turn ID。工具折叠、原文按页读取、长消息分段展开、关联产物单独展示。预览不启动 CLI，继续会话才进入原会话。
- 首次整理后由文件监听、回合事件、定期对账触发增量更新。解析在独立 worker，读取在原查询子进程，写入由 SQLite 中的唯一租约控制；worker 异常由父进程精确回收该 token。重启复用索引；全量重建收进高级诊断。
- 已有结果在后台更新时保持不动，提示用户刷新。小窗口在列表与预览间切换，桌面支持拖动分隔线。

## 验证与运行边界

新增回归覆盖超过 6000 条后的筛选召回、时间语义、排序、预览定位、快照分页、长消息、共享租约、writer 崩溃恢复、外部文件保存自动更新和重启复用。

真实规模使用生产数据库的只读 SQLite online backup：3,349,266,432 字节、4,246 会话、382,614 记录。12 次代表查询均完整完成，首批约 0.06–0.27 秒，常见完整查询约 0.3–2.1 秒。数据和计时只代表本机样本；未完成扫描时 UI 始终明确显示继续检索。原有 35 个不完整/异常来源仍在覆盖统计中，不能宣称全库已无缺失。

端到端脚本：`node tests/e2e-global-session-search-cdp.js`。使用隔离 home/data 和独立 CDP 端口，覆盖七天筛选、来源/内容范围、原生卡片、XSS、键盘、窄窗口、继续会话和打开群聊。

完整闸门：`node scripts/run_unit_tests.js`；Windows 测试进程的 PATH 需要包含 `C:\Program Files\Git\bin`，供已有工作流测试启动 sh。不要为此修改全局环境。

M4 的 BM25、查询偏好学习和模糊纠错不在本次实现内。旧解析器的来源/文本上限继续通过 staleSources 与诊断报告；本次没有偷偷扩展“完整索引”的含义。

作者在隔离 worktree 提交；独立合并位对冻结 SHA 执行 `python scripts/merge_task.py <SHA> --dry-run` 和正式合并。版本号由脚本更新，生产工作区两个无关未提交文件必须保留，生产 Hub 进程不得重启。
