# 硬盘管理

2026-10-04，初版硬盘释放已合入；本次范围扩展为候选，尚未合入生产。

## 需求与操作

C 盘曾达到约 98%，大量空间被旧的隔离测试数据、下载缓存和 Android 测试设备占用。底部「硬盘」百分比现在是独立入口：点击打开清单，勾选项目，查看确认页，再明确确认清理。CPU / 内存入口继续打开原有内存释放面板；两块面板互斥。

后台扫描有可见进度，清理后报告执行前后真实磁盘可用空间的变化，以及每项完成或保留的原因。清理中关闭面板不会中断删除，再次打开能查看进度和结果；扫描中关闭会取消扫描。清理回执保存在 Hub 数据目录的 `disk-release/`。

## 可清理范围

- 用户临时目录中，名称符合已知 Hub / 助手 / 投研测试前缀且带隔离数据标记的旧测试目录。最近 48 小时有更新的保留。
- 用户临时目录与 `C:\VibeData\Temp` 中的 Hub 测试数据均适用上述名称、标记和 48 小时保护规则。
- npm `_cacache`、pip `cache`、uv `cache`、Yarn `Cache`、Gradle `caches`，保留已安装环境和工具；以后安装或构建可能重新下载、生成缓存。缓存包含与其他文件共享的硬链接时整项保留，避免误报预计可释放空间。
- Chrome、Edge 的用户数据目录，以及 `C:\VibeData\BrowserProfiles` 中的 Chromium 配置，只允许清理带 `Preferences` 标记的 profile 内的 `Cache`、`Code Cache`、`GPUCache` 三类目录；不选择整个 profile，保留 Cookie、History、Preferences、书签和登录。浏览器进程存在时保留全部相关缓存；Java / Gradle 进程存在时保留 Gradle 缓存。执行前再次检查。
- `C:\VibeData\Temp` 内按日期命名的 Android 测试设备。需要手动勾选，确认页说明虚拟设备及其登录状态会删除。

这是指定位置的清理器，不是全盘文件删除器。正式聊天历史、登录配置、源码、系统文件、开发环境不作为清理目标；包含 `.git`、`node_modules`、`.venv` 或目录链接的测试目录整项保留。活动进程引用目标、开发进程身份不可确认、依赖安装正在进行、模拟器正在运行时，相关项目保留。

## 大目录占用分析

面板分为「清理数据」与「查看大目录占用」。占用分析由用户点击后在后台执行，覆盖桌面、微信文件、Claude / Codex / Hub 历史、Android 设备、Conda 环境、应用本地数据、Vibe、AIWork、VibeData；显示实际文件占用、位置、最大的八个已核对子目录，以及对应整理建议。占用结果不产生清理 key，不提供删除操作，也不使原有清理清单失效。

快速分析优先访问同层的各个子目录，再进入更深的环境，避免预算耗在单个任务。每个大目录最多列举 25,000 个文件、10,000 个目录，列举时间最多 5 秒；随后调用 Windows API 核对已列举文件的实际分配空间，时间上限不包含这一步。读取受限、数量或时间达到上限、目录链接跳过时明确显示 `≥`，表示部分结果。按已核对大小排序，未完成项目的真实占用可能更大；不把逻辑长度替代读取失败的实际占用，不把共享目录结果相加成全盘总量。目录内重复硬链接去重，跨分类共享文件不作全盘总量声明。

分析结果留在当前窗口，重新打开可查看核对时间；手动「重新分析」刷新。关闭分析会取消，不影响清理清单；清理中关闭面板仍继续执行。UI 扫描与清理串行，使用独立 Worker，不阻塞主窗口。大目录分析不等于全盘审计；需要完整审计时仍应单独执行并说明耗时。

## 删除边界

扫描与实际删除在 Worker 中执行。文件路径通过 JSON 输入交给隐藏 PowerShell，禁止拼接成命令。预计空间通过 Windows `GetCompressedFileSizeW` 核对实际占用，避免把模拟器稀疏文件的逻辑长度算成可释放空间。Windows 进程枚举可能留下已退出进程且命令行为空的瞬时记录，额外核对进程是否存在，仅剔除已确认退出的 PID；进程仍存在或访问受限时继续保留相关数据。

扫描产生十分钟有效的私有清单；执行只接受本清单的随机 key 和明确确认，不接受调用方传入的删除路径。执行前重新检查活动进程、整个文件清单、大小、更新时间与文件身份。逐个删除前再次检查真实目录边界、祖先链接和文件身份；文件变化或检查失败时保留。只逐文件 unlink、空目录 rmdir，不穿透 junction。Windows 命名管道实现跨窗口清理互斥，崩溃后由操作系统自动释放。

空间变化可能受其他程序同时写盘影响，因此最终显示磁盘净变化，而不是承诺一定释放预计大小。扫描采用进程信息和更新时间判断使用状态，不替代 Windows 文件锁；被占用且不能删除的文件保留并报告。
