# CodeAgent 所选账号与认证来源一致

## 问题与行为

Hub 从 CodeAgent 的进程树启动时，可能继承 `CODEAGENT3_X_AUTH_TOKEN`。旧实现仅切换账号配置目录，子进程仍得到父账号的令牌，所选账号与实际认证可能不一致。

新建 CodeAgent 子进程时，账号目录有非空认证内容、且按现有登录状态判断可用，才从子进程环境副本中移除父账号令牌。缺失、损坏、过期的 IDaaS 凭证，以及只有账号/到期元数据的文件，都保留原有环境令牌登录能力。DevUC 保持原有自动续期语义，可识别非空刷新凭证。

不解密或返回凭据。主进程环境、工具守卫、代理、证书和模型设置保持原值。原地重拉复用已有终端环境，命令构造函数不修改传入环境，也不声称旧终端已重新认证。

## 覆盖入口

会话新建与历史恢复、后台标题生成、账号模型探测、登录窗口和版本查询统一使用 `core/codeagent-launch-env.js`。启动日志仅记录认证来源枚举和是否忽略了继承令牌；远程诊断仅记录令牌是否存在，不回传内容。

## 验证

- 单测覆盖所选个人/号池账号、环境变量大小写、自定义配置变量、缺失/损坏/过期/空认证、DevUC 刷新凭证，以及原地重拉不改 Hub 主进程环境。
- `tests/e2e-codeagent-auth-isolation.js` 用隔离 Electron、真实终端子进程和合成凭证验证个人号、号池号、仅有元数据三种启动情况；检查工具守卫、代理、证书和模型配置。
- 此测试不调用公司模型，不能证明公司当前配置改写的进程来源。公司验收应先看存在性诊断，再做一次只读问答并核对实际模型和后续 settings 变化。
