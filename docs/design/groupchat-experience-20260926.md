# AI Hub 交互统筹与验收

用户目标：从整体设计视角清理历次开发形成的重复 UI 与功能，交付经过验证并合入主干的版本。头像指定收件人是已确认的交互约束。

## 统一职责

| 界面 | 唯一职责 | 应移除的歧义 |
| --- | --- | --- |
| 输入框头像 | 决定下一条话发给谁 | 不用工作流角色、正文 @ 或回复状态暗改收件人 |
| 群成员栏 | 管理成员、打开 CLI、查看个体状态 | 成员总数不再冒充选中收件人数 |
| 工作流进度 | 说明当前步骤、交付与可执行的下一步 | 不把回答结束数当成交付进度；暂停、接续不同时堆叠 |
| 聊天时间线 | 用户要求、AI 回复及必要事件 | 自动派工不署名为“我”；文件协议默认收起但原文可查 |
| 群聊工具 | 搜索历史、查看详细轮次 | 不承担另一个流程控制中心 |
| 工作目录与任务文件 | 分别查看项目文件、当前任务交付 | 标明范围，避免两个同名文件入口 |
| 首页和功能导航 | 进入对应工作空间 | 活动群聊不得与欢迎页争夺主要阅读空间 |
| 账号、能力、记忆等全局页 | 管理全局资源 | 不重复创建群聊专属设置与在途任务状态 |

## 交付顺序与验收依据

1. 头像投递和阶段联动：已有候选 558a24a；真实 CLI 接收、持久回执和阶段不变均有证据。全量测试尚未放行。
2. 工作流控制与聊天可读性：默认展示状态、一个主要操作及交付文件；高级恢复/结束操作按需展开；原文不删。加载和失败都有明确重试入口，切群期间迟到响应不操作新群。
3. 群聊布局和导航：检查普通群、文件工作流、旧开发群、成员双屏、工具展开、小窗口与空选择；核对入口作用和重复状态。
4. 全局入口审计：检查首页、工作台、备忘录、记忆、工具、账号的入口归属，以及本轮其他工作位正在改的初心内导航。保留不同职责的入口，不按视觉相似就删除功能。
5. 集成：独立审查；真实隔离 Hub 与 GUI 证据；全量项目验证；核实其他在途合并结束后走项目合并入口，升版本、推送、核验主干。

完成标准是上述范围在最终主干上的证据，不以候选提交、单元测试或设计文档代替。当前仍在实施；不改生产实例，不合并或清理他人的未提交文件。
