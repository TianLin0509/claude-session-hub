# 公司 AI 文字任务与固定海报模板

## 用户行为

公司版草稿整理、自动标题、团队周报的整理/摘要/事实核对、风格地图分析统一交给当前电脑的 CodeAgent。后台任务不切走用户正在编辑的会话。语音仅本地识别；本地识别失败保留录音并提示，不回退外部 API。旧版造梦流程提示使用现有的新造梦入口。

海报提供横向简报、进展与计划、四项重点三个固定模板。CodeAgent 只返回经过字段和长度校验的 JSON。服务器用既有 Pillow、标准库 ZIP/XML 生成 PNG 和原生文字可编辑的 PPT。超出可读字号时明确失败，原材料保留，不静默截断。事实核对以原材料和实际排版文字为依据，疑点由用户确认。

## 会话执行

每个请求创建独立普通 CodeAgent 会话，最大并行 2 个，排队上限 30。通过正式 prompt 提交管线发送，使用随机回执匹配原生最终回复。每项任务独立目录和会话，避免草稿串话。完成后关闭本任务会话，重启将未完成任务标记为中断，不自动重发。禁用通用 Hub MCP；提示词约束任务只处理材料，这不是操作系统级沙箱。

## 团队网页接入

网页继续使用原有隔离容器，不注入 Hub IPC。主进程仅向团队目录中允许的 HTTPS 主机及路径注入每安装随机令牌。服务器返回协议标识后，主进程轮询当前令牌对应任务；服务器持久化队列并按令牌隔离领取、随机回执确认回写。回写重试只重传结果，不重复启动模型。令牌属于安装，不等同于企业身份认证；沿用原网页用户权限。

服务器只持有业务数据与任务队列，不持有模型 API。公司电脑必须保持 Hub 运行并登录 CodeAgent；独立浏览器不具备执行能力，页面明确提示从公司 Hub 操作。重启、超时、返回格式错误均保留材料，允许用户主动重试。

## 发布与回退顺序（尚未执行）

1. 本地候选通过全量单测、独立 Hub 界面测试和三套周报/风格地图隔离接口测试后，按仓库 `scripts/merge_task.py` 合入；由合并入口抬源版本，再重新导出公司 4.1.1。
2. 公司导出代码与云端补丁须配套升级。先发布并确认公司电脑实际升级，再切换云端服务；旧云端未声明协议时新 Hub 不会发起文字任务轮询。
3. 对云端四个服务分别停止其确切计划任务、备份源码与数据库（数据库用 SQLite backup 或停服务后一致副本），核对候选清单 `before_sha256`。任一文件漂移即停止覆盖，重新比较现网。不得覆盖配置、密钥、数据或用户生成物。
4. 应用完整同版文件集合，启动原计划任务：TeamWeeklyAPI、AITeamWeeklyAPI、WeeklyPlatformAPI、StyleMapGate。验证页面版本、CodeAgent 真实会话、整理、摘要、三模板、PPT 下载、核对，以及历史记录；HTTP 200 不能代替实际验收。
5. 失败时停止本次服务、恢复源码备份，保留新增任务和生成物；数据库涉及版本兼容时保留当前库并从备份复制出回退库，不直接覆盖用户新写入。记录回退时间及未完成任务。

云端部署根：`C:/TeamWeekly`、`C:/AITeamWeekly/app/weekly_engine`、`C:/WeeklyPlatform/app/template/weekly_engine`、`C:/stylemap/app`。最终候选清单逐文件含旧/新 SHA256；模板依赖云端已存在的 Pillow 与微软雅黑，不安装新的服务依赖。

## 验证边界

原生界面测试使用真实 Haiku 作为本机 CodeAgent CLI 替身，验证正式会话/提交/回执及草稿撤销；不代替公司原生 CodeAgent 验收。网页端到端使用真实页面与服务器、合成模型回复。PPT 经结构、可编辑文字验证，以及本机 Microsoft PowerPoint 对三套长文本模板的打开和 PNG 导出验收。正式云端部署与公司设备升级属于后续发布步骤。
