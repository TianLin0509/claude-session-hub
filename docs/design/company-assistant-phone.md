# 公司版助理 · 手机对话（2026-10-18）

在手机 WeLink 的一个专用群里和公司「助理」说话；由助理去管这台电脑 Hub 里的其他 CodeAgent 会话。只在公司版启用（随 `features.companyAssistant`）。

## 为什么是「只和助理说话」

用户 10-18 定的方向：
- 不做「指令遥控」。如果把整个 Hub 搬到手机上，指令多、要记，也费时间。
- 手机上永远只和助理对话，用自然语言问「现在有哪些会话」「让某某接着做，做完告诉我」。
- 助理用工具去看、推进、新开其他会话。

这和家里的「AI Hub 助理」App 是同一个思路，只是公司要求用 WeLink，所以通道换成 WeLink 群。

## 通道：用户自己建的专用群

- WeLink 不允许自己给自己发消息（公司同事 WeRemoteControl 帖子原话，Q-1018-04），所以必须用群。
- 建群至少要 3 人。用户自己在手机上操作：
  1. 拉「小微助手」和一位同事建群；
  2. 把同事移出，群里只剩本人和小微助手；
  3. 群名改成「助理 CodeAgent」。
- 然后在助理设置的「手机」页从群列表选中这个群：
  - 「检查群成员」会提醒群里是否还有别人；
  - 勾上开启并保存后，Hub 往群里发一句「已接通」，同时验证能发进这个群。
- welink-cli 1.0.14 没有推送、机器人、webhook，所以 Hub 每 3 秒查一次群消息（`im query-history-message --message-id <游标> --query-direction 1`）：
  - help 里写的查询方向和实际相反，1 才是「更新的」；
  - 公司实测每 2–5 秒查一次，66 次全部成功，没有被限频。
- msgId 是超过 JS 安全整数范围的长整数，解析前先改成字符串，比较时用 BigInt（`welink.js` 的 `groupMessages`）。

## 防误触发与越权（借鉴 WeRemoteControl）

- 只认这个群里本人账号（`auth status` 的 UID）发的文字，小微助手和其他人发的不理。
- Hub 发出的消息都以「【助理】」开头，并记下摘要，不会被当成指令。
- 去重：同一条消息只处理一次。
- 新鲜度：
  - 超过 120 秒的旧消息不执行，所以 Hub 重启后不补跑积压；
  - 刚接通或刚换群时，只认接通之后发的消息。
- 限流：每分钟最多 20 条。
- 写命令只有一条：往设置里选定的群发文字。`welink.js` 的 `sendAllowed` 要求群号一字不差，只有 Hub 主进程会传这个群号。助理会话用的只读包装 `welink-ro` 仍然发不了消息。

## 助理的会话工具（`hub-tools.js`，MCP 名 `hub_sessions`）

| 工具 | 作用 |
|---|---|
| list_sessions | 列出会话及其状态：卡住等确认 / 运行中 / 答完等回复 / 空闲 / 没打开 |
| read_session | 看最新回答；会话卡住时附终端画面 |
| send_session | 给空闲或已答完的会话发话；没打开的先恢复 |
| create_session | 新开一个 CodeAgent 会话并交代任务 |
| watch_session | 盯着一个会话：下一次答完或卡住时推到手机 |
| press_keys | 会话卡住时替用户按键（数字、回车、Esc、方向键等白名单） |
| stop_session | 停止正在运行的一轮 |

- 用户 10-18 选的是「直接执行，事后复述」，不加确认步骤。
- 只有公司助理会话能调这些工具：本机接口要口令，还要按请求头里的会话编号核对身份。
- 不碰这些特殊会话：
  - 助理自己、论坛摘要；
  - 替家里办事的会话（company-bridge），因为内容会被带回家；
  - 群聊成员。
- 发过话的、新建的会话会自动被盯着。
- 公司 CodeAgent 用的是 Claude 格式的 `--mcp-config`。原来「家里联动类会话不挂 Hub 的 MCP」这条规则，给 company-assistant 开了例外：它的额外配置里只放这一组工具。
- 旧版本的助理会话启动时没挂工具，所以按 `TOOLS_VERSION` 换一个新会话，旧会话留在历史里。

## 推送

- 盯着的会话答完时，推一条「「标题」这一轮答完了：……」，带回答前 600 字；推过一次就不再盯。
- 盯着的会话卡住时，一定推，附等待提示或终端画面末尾 10 行。
- 其他会话卡住时也推，但电脑前 5 分钟内有键鼠操作就不推（`powerMonitor.getSystemIdleTime`）。
- 同一次卡住只推一次。
- 手机问的问题 20 秒内还没答完，先回一句「收到，正在处理…」。

## 测试

- `tests/unit-company-assistant-phone.test.js`，覆盖：
  - 只放行选定的群；
  - 长整数游标；
  - 全流程：接通、本人新消息、回答发回群里，Hub 自己的话、小微助手、旧消息都不处理；
  - 关闭后不再收发；
  - 工具的身份校验和特殊会话排除；
  - 发话后盯着、答完推送；
  - 卡住时按键；
  - 卡住推送的「人在不在电脑前」规则；
  - MCP 走 stdio 能调通、会话编号不对时被拒。
- `tests/e2e-company-assistant-phone-real.js`：隔离 Hub，配假 welink-cli 的专用群和 CodeAgent 替身（真 Claude Code + Haiku），按真实点击路径走：
  1. 设置「手机」页选群、检查成员、开启；
  2. 手机问有哪些会话；
  3. 手机派活；
  4. 被派活的会话答完后推到群里；
  5. 核对写命令只有往这个群发消息。

## 没验证的

- 真机 WeLink 上的几件事：
  - 单人群（只剩本人和小微助手）能不能保留；
  - 小微助手会不会在群里自动接话；
  - `send-to-group --text` 能不能带换行，单条最长多少字（现在按 1500 字切分）；
  - `auth status` 的 UID 和消息里的 sender 是否同一格式。
- 这些都要等用户在公司电脑上第一次接通时确认。不对的话，在「手机」页的「最近往来」里能看到消息被拦下的原因。
