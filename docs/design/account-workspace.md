## 2026-10-08 · 不再自动访问网站（覆盖下节的后台确认方式）

事故：10-07 版的后台确认在用户刚重启 Hub、正手动使用 ChatGPT 时，在同一个专属 Chrome 里自动打开 chatgpt.com 与 claude.ai，两站都被 Cloudflare 拦截（ChatGPT 主号第 3 次），自动化失败把 `cf_chl_rc_ni` 等验证失败计数 cookie 累积在用户的资料里，用户点「Verify you are human」3 分钟内循环 10 余次。另外 `resetChallengeCookies` 用 `Storage.getCookies` 读主资料的 context 一直报错且被吞掉，此前「去验证」清计数从未生效。

- 例行确认（启动后、约 12 小时一次、打开后复查、更多菜单「立即确认登录」）**只读本机登录 cookie**：Chrome 关着读磁盘副本，开着经该身份的本地标记页读取，不访问任何网站。cookie 缺失或过期才算掉登录；没有登录 cookie 的站点（DeepSeek、Kimi、千问）不检查，靠工具使用记录。结果写 `source: 'cookie'`、`live: false`，生图工具不会据此解除人工关卡。
- 只有用户亲自点「复核并继续原任务」才访问那一个网站（网页圆桌恢复需要新鲜证明）。
- 「需要重新登录」与红色角标只算真实掉登录（cookie 消失、工具报需登录）。工具遇到人机验证、站点被挂起只显示为灰色备注「网页工具遇到网站验证；你自己使用不受影响」，不计角标、不把按钮变成「去验证」。安全暂停（`safety_hold`）和后台检查自己造成的挂起不显示。
- 清验证 cookie 改经标记页 `Network.getAllCookies` 读取。人打开 24 小时内被拦过的站点前，只清失败计数 `cf_chl_*`（保留 clearance 与登录）；站点挂起期间的「打开」仍走人工接管并清全部验证 cookie。

## 2026-10-07 · 简化：打开永不被拦、一行状态、红色角标

起因（生产实测）：10/6 一次中断的检查留下一个只有标记页的无头 Chrome，之后账号页每次点「打开 / 去验证」都报「正在后台检查登录」；账号行堆了四五行来源说明；网页生图车道 9/30 起卡在人工关卡。用户要求账号页只做：点了就打开网页、权限失效时提醒、记录上次同步时间。本节覆盖下文与 `account-center.md` 中「检查期间不能打开」「打开一律用普通窗口」「浏览器有工具页面就拒绝」的规则。

- **打开永不被拦**：后台检查不再阻塞任何人。点击或工具需要浏览器时写 `locks/account-check.yield`，无头检查在两次读取之间停下、关掉自己的浏览器、保留已完成结果；同一 Hub 内直接中止。没有检查却存在的无头 Chrome（只含标记页）视为遗留，由下一次打开或工具调用关闭。
- **打开方式**：专属 Chrome 已在运行（工具在用）→ 在其中开一个屏幕上的新窗口，不附着调试器、不关工具页面；没有运行 → 启动调试模式的专属 Chrome 再开窗口，让工具与人并存；普通窗口开着 → 加标签页。「去登录」仍优先普通窗口（Google 登录拒绝调试端口），工具有页面时改在运行中的 Chrome 里打开并提示；「去验证」的人工接管同理，接管在该窗口关闭后结束。
- **一行状态**（`core/hub-account-health.js`）：证明登录有效 = 检查确认已登录（`last-check.json` 另存 `lastSignedInAt`，被新结果覆盖也不丢）或生图 / 圆桌 / 中转成功；问题 = 检查发现退出、工具报需登录或人机验证、站点被网页工具挂起。较新者胜。打开网页刷新「上次同步」但不算证明。从未登录过且只被检查发现未登录的站点显示「未登录」，不计角标。检查本身被网站验证拦截不算问题。
- **后台确认**（`HubAccounts.startAuto`）：每分钟轻量判断，约 12 小时全量确认一次（失败 30 分钟后再试）；用户打开过的非正常账号 90 秒后复查，之后每 5 分钟一次、最多 1 小时，登录后角标自动消失。专属 Chrome 运行中就在后台标签页里查，否则用无头；普通窗口开着或人工接管中跳过。隔离实例只有设置 `HUB_ACCOUNTS_AUTO=1` 且有夹具时才跑。
- **角标**：主进程按「需要处理」的账号数推送 `hub-accounts:attention`，侧栏「账号」显示红色数字；页面关着也会更新。
- 网页工具读取的 `last-check.json` 字段（`identities.<id>.sites.chatgpt` 的 `state/live/verified/checkedAt`）保持不变，生图 MCP 用它在用户确认登录后解除人工关卡。

验证：`node --test tests/unit-hub-account-health.test.js tests/unit-hub-accounts-workspace.test.js tests/unit-hub-browser-human-mode.test.js tests/unit-web-risk-guard.test.js`；`node tests/e2e-hub-accounts-yield.js`（真 Chrome、本机夹具网页、窗口在屏幕外）；`node tests/e2e-account-center-cdp.js`、`node tests/e2e-web-risk-account-page-cdp.js`（隔离 Hub、鼠标点击、角标颜色与计数）。

## 2026-09-27 · A 清透白与被动使用记录

2026-09-28 修正：旧版只读取新建的事件文件及“当前绑定仍完全一致”的生图队列，遗漏了专属 Chrome 原有的网页访问历史；工具入口后来变化时，生图记录也会整批消失。现在被动读取主、副 profile 的 Chrome History 快照，以“访问过网页”显示已存在的访问时间，不把访问解释为登录成功。生图绑定变化时页面直接说明记录暂不能归属共享账号。读取不启动浏览器，每个 profile 最多 30 秒重新读取一次；公开状态只输出站点、槽位、时间和事件类型，不输出访问 URL。宽屏内容限宽并居中，账号页使用项目已有 AI 图标；大屏导航在账号页展开，窄屏保留原紧凑导航。随后主干新增「投研数据」分类，当前为六分类，历史五分类方案仅作设计记录。

本节按用户最新选择覆盖下方旧版的卡片布局、主动检查和混排设计。账号页使用白底、浅灰公司标题和蓝色操作，五个分类为 AI 网页、工作平台、内容平台、命令行授权、API 与服务。默认列表只呈现账号、最近使用和打开入口；添加第二账号、切换默认账号在更多菜单，工具连接默认收起。不增加总览指标、批量操作或主动检查入口。

进入页面与定时刷新只读本机记录，不启动网站检查。网页打开成功只记“打开过网页”；圆桌成功记“使用成功”；生图读取原队列的成功/限流/登录异常，并核对账号与当前工具绑定。失败不会抹掉最近成功时间，限流不等同退出登录。公开状态仅包含时间、账号槽位、来源与结果，不输出提示词、回答、密钥或图片路径。CLI/API 保留原工具授权，不能拿网页登录替代。

新增 `core/hub-account-activity.js` 负责被动记录与生图只读投影，`renderer/account-workspace-view.js` 负责分类和展示。页面关闭后停止轮询；历史检查后端为旧调用保留兼容，但新页面不会调用。网页圆桌仍用 main，双生图和中转绑定不变。

## 2026-09-26 · 历史设计

本文件取代 `account-center.md` 中 2026-09-25 的主／副身份卡片布局。源需求：按公司展示 1～2 个账号，复用用户最近登录的 AI Hub 专属 Chrome，提供 AI 网页快捷入口；登录检查真正无头、低开销、有进度。

## 用户操作

- 七家公司：OpenAI、Anthropic、Google、字节跳动、DeepSeek、月之暗面、阿里巴巴。公司卡片内显示网页产品、账号、状态、打开网页按钮。命令行授权按公司折叠保留，凭据仍由各 CLI 自己保管。
- 每家默认一个账号，ChatGPT 保留已有两个。可添加第二个账号，选择默认打开账号；不删除、覆盖或搬动原 profile。`main`、`alt` 继续复用既有 Chrome 目录，每个网站各自确定身份，不用 ChatGPT 邮箱给其他网站认人。
- 网页按钮和账号页内的 Alt+1～7 走同一入口。输入框、配置页、其他会话、组合输入期间不截获快捷键。明确需要登录的账号走普通 Chrome 登录入口；已有受管 Chrome 中的日常网页可独立打开，不关闭工具页面。
- 普通模式的 Chrome 正在使用资料时，不能同时以无头方式占用同一资料目录。检查会明确提示先关闭专属网页窗口；不强关窗口、不复制 Cookie、不悄悄改用屏幕外有头检查。受管工具占用期间同样如实提示。
- 登录检查串行执行，至多一个 Chrome 主进程、一个检查页面。每个 profile 检查结束即释放，再检查另一个 profile。当前网站、账号、阶段、已完成数可实时读取；取消后保存已完成项，清理完成才报告已取消。
- 开页与定时刷新只读取状态；页面隐藏即停止轮询。检查中每 500 ms 读取进度，闲置时 15 秒读取本机状态。Cookie 和历史结果不作为新鲜官网登录证明；官网无法确认时显示未知或需人工验证。

## 网页工具统一接入

账号页的「统一接入专属 Chrome」发现已安装生图队列和中转配置，只读取标签与配置路径。用户显式选择每组工具对应的 ChatGPT 账号。空标签不猜；同一组的并发车道按组绑定。

接入沿用 `configure-hub-browser-tools.py` 的事务入口：核查无在途任务 → 给指定 worker 写原工具支持的停止标记并等待正常退出 → 持有 worker、队列与操作锁 → 关闭工具自己的旧页面 → 原子替换浏览器入口并保留备份 → 撤回本次创建的停止标记。保留已有停止标记，不取消任务、不重发 prompt、不复制凭据、不改中转游标。

生产工具入口必须指向稳定主目录。未合入的 worktree 拒绝绑定真实工具；隔离验证使用 root 内的 `tool-fixtures`。合入后从账号页完成实际账号选择与接入。原生 CLI 与其他外部客户端自己的令牌不搬入 Chrome，网页登录与 CLI 授权分别确认。

## 模块与边界

- `hub-account-catalog`：公司和产品目录；`hub-account-preferences`：启用第二账号和默认网页账号。
- `hub-accounts`：公开状态、检查任务、身份证据、任务恢复；`hub-login-check`：串行无头探测与资源归属。
- `hub-chrome`：Chrome/profile/页面与生命周期互斥；`hub-account-browser`：旧账号 IPC 的共享浏览器兼容入口。
- `hub-browser-setup` + `scripts/hub-browser-setup.py`：安装工具发现、实时接入进度与旧入口迁移；原 `hub-browser-tool` 负责实际页面传输。
- renderer 只展示状态与发送选择；IPC 校验公司和账号，不能从页面提交任意 URL、路径或执行命令。

网页圆桌仍沿用 main 身份；本次默认账号选择只影响日常网页快捷入口，不改正在执行的圆桌或生图任务身份。检查只用本次取得的新鲜证明恢复等待任务，并在检查浏览器退出后恢复；旧证明不能触发续发。恢复失败保留登录结果并单独显示原因。
