# 群聊头像收件人与工作流联动

2026-09-26，用户要求：群聊输入默认按输入框头像勾选发送，活跃 CLI 也能收到新 prompt，头像随工作流联动。

- 收件人使用点击发送瞬间的 session ID 快照，服务端核实属于本群。空选择或已移除成员明确拒绝，不回退全员；正文里的 @ 不偷偷扩大这份快照。
- 活跃文件任务的输入为补充，不重启任务、不自动恢复用户暂停、不更改交付或轮次。原有接续按钮承担恢复职责。选中的已打开成员（空闲或执行中）即时走现有提交闭环；未打开成员不擅自唤醒，明确显示待送达。
- 保存新工作流时选中首步成员；进入新步骤时选中本步成员。同一步内的刷新、交付、暂停、恢复不覆盖手动选择。首次启动仍按配置的首步；如手动选择与首步不一致，保留输入并明确提示，不能向未勾选的人启动任务。
- 普通群聊同样固定发送时头像快照。旧循环的补充复用相同收件规则；旧开发文件协议沿用已有阶段联动及入口。
- 用户补充按原文落盘，保存收件人及标签。已受理、CLI 已排队、待送达、待核对分别展示。没有确认的提交不当作成功，也不能随下次派工自动重发。
- 同一个 CLI 的提交过程串行化到受理/失败返回为止，不等待回答结束，避免补充与自动派工的粘贴块交错。
- PTY 插话按原文匹配 Claude 提交 hook / Codex 原生用户记录，不以原任务仍在运行作为新消息确认。共享回执协调器避免重复文字共用一份确认；超时后最多监听十分钟，晚到确认只更新原卡片。

验证覆盖：头像单选/多选/空选、选择变化竞态、活跃与空闲接收、步骤自动选择与手动覆盖保留、暂停插话不恢复流程、文件交付继续推进及失败原文保留。GUI 在隔离 Hub 通过真实头像和输入框操作；协议夹具和真实模型结果分别报告。
