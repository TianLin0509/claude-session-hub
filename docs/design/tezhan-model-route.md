# 家里按模型给公司派活（GLM / DeepSeek 分流，2026-10-18）

田哥：号池里两个号（自己的、同事的）分别能用 GLM 和 DeepSeek；家里的 Agent 自己判断用哪个模型，简单任务交给 DeepSeek，工作日白天给同事们常用的 GLM 分流。

> **2026-10-19 起：账号即模型（田哥：「每个账号现在都只有一个模型……直接用默认的模型就可以了，根本不用选模型」）。**
> 通道按模型派活只挑默认模型就是它的号；下文「号池的号……切默认模型、`hub-route-model.json`」那条路径收到开关后面，默认关（`AI_HUB_CODEAGENT_ROUTE_SWITCH=1` 才开）。
> 关着时同步号配置原样保留号自己 `settings.json` 的 `model`；遗留的 `hub-route-model.json` 在号空闲时按记下的原值写回一次后删除，并记一行 `codeagent-model.log`。
> 通道、公司助理、论坛三类自动会话启动和恢复都不带模型、不驱动 `/model` 菜单；恢复按号此刻的默认模型起，不「选回」旧模型。

## 链路

1. **公司 → 家里「模型表」**（`core/codeagent-model-route.js` `modelTable`）：个人账号 + 号池可用的号按模型聚合：模型名、能用的号数、通道在处理几个、还能并行几个（每号忙时 / 闲时上限 × 能接的号，再受通道整体上限约束）、是否忙时、哪个是日常主力（GLM 一族）。不含账号名、工号、备注。配对后（含公司 Hub 重启后）推一次；之后模型集合、号数、忙闲或「还能并行」的档位（0 / 1 / 2+）变了才推，最快 10 分钟一次；每份回执、以及「指定模型没有可用的号」的报错也带一份。
2. **家里存下**：数据库一份，通道目录 `company-models.json` 一份。MCP 列工具时现读它，`ask_company` 的描述末尾带模型表和选择原则；没有时写「模型表未知」。命令行 `company-ask.js models` 看同一份，`ask --model` 指定。
3. **家里 `ask_company` 的 `model`（可选）**：模型表已知时必须是表里的（大小写不敏感，按表里写法发），否则报错并列出可选项、不发出；未知时只核对格式，由公司核对。不填 = 公司默认，与以前完全相同。
4. **公司按模型开会话**：在有该模型权限的号里挑（进行中会话少的优先，其次不用切模型的，再次号池优先，最后轮转）。没有哪个号有它 → 不开会话，回执写明原因和可选模型；有权限的号都在跑别的模型或到了每号上限 → 排队，只等有该模型的号空出来，不占别的问题的名额。追问沿用原会话；会话休眠后恢复仍按原模型（`codeagentRouteModel` 随会话持久化）。
5. **界面**：特战会话名不变（`1018-Q1-codex`），CodeAgent 卡片显示所用模型；通道串、家里「问公司」列表和公司「AI特战队专用功能」的任务列表显示指定 / 实际模型。设置里没有新开关。

## 怎么让会话用上指定模型（取舍）

- **为什么通道会话原来不传 `--model`**：公司 CodeAgent 交互模式不认 `--model`（2026-10-13 真机三轮排查：启动画面写着 MiniMax，回答仍是 GLM；`--settings`、环境变量、`/model <名字>` 也不生效，只有 `-p` 一问一答认）；能用的只有 `/model` 菜单，但它在公司真机上把第一条消息卡住约 1 分钟（2026-10-15 田哥反馈），所以通道会话一律用号的默认模型、不走菜单。
- **选的路径**：号配置目录 `settings.json` 的 `model` 决定新会话的模型——2.1.8 起号池同步配置就靠它把 DS 号定到 DS（修「DS 号报找不到 GLM」），`/model` 菜单按回车也是把默认模型存进这里。不触发任何菜单，也不在命令行加不生效的参数。
- **号池的号**：Hub 管它的配置目录。默认模型就是指定模型的直接用；两个模型都有的号，只有它上面没有进行中的会话时才切（CodeAgent 可能在会话中重读设置，切了会影响正在跑的会话），切之前的模型记在 `hub-route-model.json`，之后不指定模型、号空闲时换回，不指定时的行为不变。
- **个人账号**：号主自己日常用的配置，不切；只有它此刻的默认模型（按下文「v2.1.11 真机反馈的修正」纠正后）就是指定模型时才用它（个人账号 GLM、号池同事号 DS 的组合正好覆盖田哥说的两个号）。
- **不静默换模型**：挑不出号时不退回个人账号或别的模型；回执另记 `requestedModel` / `actualModel`（回答里实际出现的模型），不是同一家时家里提示里明说。

## 审核后的补充（2026-10-18）

- 隐私：通道会话（purpose=company-bridge）的号池报错只写「号池里的一个号」，哪个号只记本机日志；公司一端发回家里的 `status` / `reply` / `hub-admin-status` 里的说明与报错再统一脱敏（号池编号、工号掩码、备注、显示名，以及掩码样式兜底）。
- 「能用」只算真能派的号：个人账号只算它此刻的默认模型，不在表里列它切不过去的模型，指定了也直接回「没有可用的号」；号池号一直有会话、切不过去的，最多等 10 分钟，超时回原因和「现在可直接用的模型」。
- 不指定模型时，挑号避开「为通道切过模型、上面还有会话」的号；只剩它时照用（或恢复到这样的号），回执元数据写实际模型（`codeagentLaunchModel`）。
- 「CLI 没就绪」「等切模型」的起算时间不跨进程沿用，新进程第一次重试从头算。
- 家里模型表未知时指定模型，`ask_company` 返回提醒可能不生效；回执里公司没确认指定模型（旧版）或没从回答里确认实际模型时如实写。

## v2.1.11 真机反馈的修正（2026-10-18）

田哥公司真机：①通道只开号池里同事的 DS 号，从不开他自己的个人账号（GLM）；②DS 的会话被标成 GLM；③输入框下方只写「CodeAgent 当前模型」。

- **不指定模型也轮转到个人账号**（`pickAnyRoute`）：2.1.8 起「号池有可用的号就开在号池，个人账号只在号池开会话失败时兜底」，并行上限却把个人账号算作 1 条通道。现在候选是个人账号 + 号池里能用的号，依次按每号上限 → 进行中会话最少 → 上次分配时间轮转 → 全同时号池优先；避开为通道切过模型且还有会话的号、清单未知的号池号（只剩它们时照用）。挑中号池号就带该号开（`codeagentPoolPick`），挑中个人账号就按个人账号开；号池开失败仍退回个人账号。个人账号的上次分配时间单独存在 `codeagent-pool/personal-assigned.json`（以前恒为 0，平局永远是它）。
- **个人账号的进行中会话数包含号主自己手动开的、助理和论坛的会话**（`main.js` `routeAccounts`）：有意如此，号主自己忙的时候个人账号少接通道的活。
- **个人账号的默认模型按号池同一套「不在清单里就纠正」**（`codeagent-pool.js` `personalDefaultModel`）：写了且在清单里就是它；分档名 `GLM-5.2-WX` 归到菜单里的 `GLM-5.2-WX-Auto`；没写时取探测文件标的默认 → CodeAgent 自己的默认 GLM-5.2-WX-Auto → 清单第一个。2.1.11 要求「写了且在菜单里」，没写或写分档名时个人账号整个从模型表消失，指定 GLM 被回「没有可用的号」。纠正结果只用于判定和显示，不改写个人账号的 `settings.json`。指定模型时，个人账号纠正后的默认等于指定模型就和号池号一起参与挑号。
- **显示**：沿用 CodeAgent 当前模型的会话，内部 `currentModel.id` 仍为空（第一条回答到了按实际模型补），显示名先填「预计模型」：恢复的会话用上一轮实际模型（`codeagentActualModel` 随会话持久化、恢复时带回）；号池号用同步配置定下的模型；个人账号用纠正后的默认。Hub 启动加载休眠会话不再拿模型清单第一项顶；唤醒合并时主进程给的显示名为空或是占位就保留本地已有的；侧栏图标在当前模型为空时看上一轮实际模型。
- **回执的模型**：发回执前从原生记录同步读一次最后一条回答的模型（`read-last-assistant.js` `readLastAssistantModelSync`），不再和异步补记实际模型赛跑。

## 手动新建的会话也按权限清单起（2026-10-22）

田哥公司真机 v3.1.4：用个人账号从启动中心建 codeagent，一开就报「API deepseek 错误」，手动 `/model` 切一下就好。根因是自动会话与手动会话走的两条路只有前者接了权限清单：

- **手动会话原来不带模型也不开菜单**：启动中心给 codeagent 收起了「模型」下拉（一号一模型），建的会话既没有 `--model`、也不触发 `/model` 菜单，CLI 就按自己 `settings.json` 里写的 `model` 起。个人账号那份配置里写着 `deepseek-v4-flash-0731`（2026-10-20 起），而它只有 `GLM-5.2-WX-Auto` 的权限 → 每次新建都撞同一个错。号池号没这个问题：启动前 `syncSharedConfig` 已按号写好自己的模型。
- **现在的规则**（`core/session-manager.js` `_createSession`）：手动新建（`freshLaunch`、非通道、非号池）时按自动会话同一把尺——`personalDefaultModel` 不传 `single` 读出来是空（配置里的值定不下权限内的模型）、而传 `single` 能给出唯一模型时，把它交给启动选型（带 `--model` + 在 `/model` 菜单里选中）。其余一律不动：清单未知、清单有多个模型、配置写的值本来就在清单里或能归进清单（`GLM-5.2-WX` 这种分档名也算）——那四种能确定的情形都轮不到这里。熔断（连续 3 次没选成、4 小时）照旧生效，跳过了在 `codeagent-model.log` 写 `pick-skipped`。
- **菜单外改选的门放宽到启动 / 原地重拉**（`main/ipc/session-handlers.js` `runCodeAgentPick`）：`automatic` 之外加上 `reason === 'launch' | 'relaunch'`；用户在界面上明确切换（`switch`）不在其列——那一路菜单本身只列清单里的模型，选不出没权限的。这门实际作用的差别要如实看：清单权威时 `pickModel` 拿着同一份 `allowedModels`，目标不在清单里就直接拒绝、根本不打开菜单（`core/codeagent-model-picker.js` 358 行），所以那条「菜单选成了清单外的模型 → 改选」的分支在真机上到不了；真正兜住的是「拒绝打开菜单 + 记一行 `off-permission` 诊断 + 报错后的当场修正 / 避让」。放宽后手动会话多出来的正是这行诊断（`fallback=user-pick`：手动会话没人自动修，等用户自己 `/model`）。
- **启动中心的口径一致**（`codeagent:models` 的个人账号分支传 `single: true`）：摘要和「默认」那一项写的就是启动会用的模型，不再是一句「沿用 CodeAgent 当前模型」。
- **这条门管的是「非通道的新会话」，不只是启动中心**（`freshLaunch`、非 `company-*` 用途、非号池）：公司助理的建会话工具（`core/company-assistant/hub-tools.js` 的 `create_session`）走的也是这条路（它建的会话没有用途标记），同样是「配置里写的定不下、清单只有一个模型」时按清单起，否则一样会撞「API deepseek 错误」。这些会话的第一条问题由 `group-chat-watcher.sendToPty` 发出，它会先等模型选完（`picker.isPicking` → `waitForPick`）再发，不抢在菜单操作中间。
- **新建后马上发第一条会等一会儿**：手动会话是用户自己发第一条，所以选模型这段时间里发出的消息会等它选完（选不动时会明确回「CodeAgent 正在切换模型，本条消息未发送」，`core/codeagent-model-picker.js` `beforePrompt`）；等的是「画出输入框 → 敲 `/model` → 选中」这几秒。
- **不改个人账号的 `settings.json`**：仍是只判定和显示，修正只走经授权的远程维护 `set-personal-model`（`core/codeagent-personal-model.js`）。
- **验证**：单测 `tests/unit-codeagent-manual-model-permission.test.js`（会话怎么定启动模型、四种不该动的情形、熔断、启动中心的摘要口径）、`tests/unit-codeagent-model-fix-fallback.test.js` 的两条 launch/relaunch；端到端 `tests/e2e-codeagent-manual-model-permission.js`（公司版导出 + 真实点击启动中心 + 替身启动参数里带 `--model GLM-5.2-WX-Auto`、模型日志 `reason=off-permission`；号池号的手动会话照旧不带 `--model`）。替身跑的是真 Claude Code，它的 `/model` 菜单里没有公司模型，所以「在菜单里选中 GLM」这一步在 e2e 里确认不了，由 `tests/unit-codeagent-model-picker.test.js`（真实抓下来的公司菜单）覆盖。
