# 助理后端切换

助理页复用普通会话。工具栏后端菜单读取 `ALL_AI_KINDS`，覆盖 Claude、Codex、Gemini、Kimi、千问、GLM、DeepSeek API 与 DeepSeek Harness；模型、思考强度、语音输入仍由普通会话管理。首次使用目标后端按助理档位创建（见下节），其余参数沿用该后端的 Hub 创建默认值。切回时保留各自历史、模型设置与草稿。菜单支持不代表账号、客户端及上游服务可用。

## 一个助理，每种后端一份原生会话

`assistant.sqlite` 的 `backendSessions` 为每种后端保存一个固定 Hub ID，`sessionId` 指向当前拥有管理权限的实体。旧单一 Codex ID 原位迁移。先事务预留目标 ID，再创建或恢复；返回身份确认后才切换活动指针。未确认的创建不重发、不新建替代实体。切换失败保留原助理。

Codex / DeepSeek API 使用原有临时 MCP 配置，Claude 使用专属叠加文件，Gemini / Kimi 使用助理工作目录里的原生工具配置，千问 / GLM / DeepSeek Harness 使用原生驱动的专属工具参数。普通会话、全局配置与其他项目工具保持原样。HTTP 调用的宿主身份及写入操作的当前用户回合 token 必须同时匹配；旧后端失去专属工具权限。当前固定助理无参数读取资料时默认返回其本轮冻结包，明确历史检索仍走动态查询，旧 token 拒绝。全部助理实体排除于业务清单、业务历史与自身派工、关注目标。

运行中、等待响应或上一条提交仍在核对的助理不允许切换。切换期间拒绝新输入与旧工具请求；成功后清空旧回合授权。弹出菜单挂在页面上，避免原生工具栏刷新导致选择控件失焦。导航离开会收起菜单。

Claude 助理专用启动叠加文件承接已授予的自动执行权限，启动和恢复不再停在首次权限确认页面。真实 CLI 会给长粘贴套上带 ID 的 `pasted_content` 包装；助理回执仅在包装完整、ID 一致、内部为合法助理上下文时解包核对，原生记录不改写。界面仍只显示用户原话，原文可展开。Codex 助理的中文弯引号使用 JSON Unicode 转义，解码后原文完全一致，短消息使用普通粘贴闭环；超过 2048 字符的请求仍走原有编辑器通道，首次长文本的可靠性尚未通过本轮验收。普通会话输入策略保持原样。

模型切换同样以原生确认作准：Claude 新版的缓存切换弹窗须核对目标后才确认；千问通过原生 `/model` 与切换后的设置写入确认，随后真实回答再次核对实际模型；DeepSeek API 的模型与推理面板复用其 Codex 引擎，仅允许 DeepSeek 目录里的模型，旧 Claude 引擎的 DeepSeek 会话不会改接 Codex。千问工具续轮产生的空 `UserPromptSubmit` 不算新的用户回合。

最终回答读取由 `final-readers.js` 按提供方选择，核对 Hub ID、原生 ID、绑定文件或驱动。最终答复是目标助手的自述，任务验收仍须另核成果。无法取得绑定原文时明确标未知，不从终端动画猜完成。

DeepSeek 的 Codex 模型目录明确使用原生 direct 工具模式，并关闭延迟工具搜索声明。真实 V4 Pro 切换曾返回 unsupported call，随后通过 shell/HTTP 绕行取得资料；这种绕行不能算工具验收通过。真实检查须同时核对原生工具调用、同一次调用的资料回执、本轮 snapshotRead 与不变的原生 ID。自动恢复会话未解决工具错误，已撤回，模型切换不额外重启会话。

委派给 Codex 系列的任务如果包含中文弯引号，使用可逆 JSON 传输保护原文；业务会话的用户卡片投影回原话，原生提交正文仍可展开核对。动作账本、幂等身份和重复检查基于原始业务文本，送达回执核对实际传输正文。传输只包含业务任务及解码说明，不授予目标助理管理权限。其他提供方和普通无弯引号任务沿用现有通道。长文本仍由原有输入机制负责。

这里的原文是助理工具提交的业务任务，不是承诺语言模型逐字转发用户请求。真实千问与 GLM 会改写用户给出的引号，任务结果仍正确；逐字转发属于单独验收项。`HUB_ASSISTANT_VERBATIM_TASK=1` 严格检查用户给定任务与工具参数相等；默认真实派工检查工具参数、原生收到的正文和业务卡片一致，两种结论分别保留。

## 跨后端的交接

Hub 当前状态、Markdown 工作档案、派工回执、关注任务共用。`assistant/CONVERSATION.md` 和 `conversation.json` 保存自然语言交接：用户输入保留原话、标注准备/送达确认状态；助理回复只收取绑定原生记录的最终回答，去重。当前回合资料含最近 12 条交接片段（长文明确标注节选）及完整 Markdown 路径。

这些文件帮助新后端接续工作；各厂商的内部对话历史仍分别保存。旧交接中的指令只作历史证据，不能授予本轮派工权限。既有会话在首次切换时补入可读取的近期助理最终答复；切换功能启用前的全部用户原话尚未追溯迁入交接文件。

验证入口：`node --test tests/unit-assistant-backends.test.js tests/unit-assistant-provider-tools.test.js tests/unit-hub-assistant-snapshots.test.js`；`node tests/e2e-assistant-backends-live.js` 使用真实隔离 Codex、Claude PTY 验证交接、草稿往返、原生身份、派工、新回复提醒及正常退出后恢复；设 `HUB_ASSISTANT_MODEL_SWITCHES=1` 验证模型切换，`HUB_ASSISTANT_KEEP_EFFORT=1` 保留首次创建的默认强度。`node tests/e2e-assistant-all-models-live.js` 验证各提供方实际资料读取与交接；`HUB_ASSISTANT_DISPATCH=1` 扩展真实派工与通知。真实账号能力缓存只读复制到隔离 home，原生回答与提交回执才决定通过。账号拒绝、套餐缺失或上游启动失败分别保留，不转成模拟通过。项目全量闸门仍是 `node scripts/run_unit_tests.js`。

## 助理档位与任务分派（2026-10-03）

助理是快速前台：默认 Claude Sonnet 5.5 · 低思考，备选 Codex GPT-6 Luna · 低思考（`core/hub-assistant/profiles.js` 的 `ASSISTANT_DEFAULTS`）。旧数据在首次就绪时迁移一次到该默认（`assistantDefaultsVersion=2`），之后完全按用户选择。手机与电脑共用一份设置：`setProfile` 先保存，助理空闲时用 `restartSession(id,{model,effort})` 按新模型重启同一原生会话（保留历史），忙时标记 `profilePending`，下次就绪再生效；休眠中的助理直接按新模型恢复。

助理分派任务用 `create_session` 的 `tier`：fast（Sonnet 5.5 / GPT-6 Luna · 低）、standard（GPT-6.1 Sol / Opus 5.5 · 中）、deep（Hub 新建会话的默认配置，省略即 deep）。用户点名的 `kind`、`model`、`effort` 优先，其余由档位补齐；点名的型号或深度不合法时在占用本轮新建名额前报错。返回 `route.label` 供助理告诉用户交给了谁。型号只写在档位表里，助理不记具体型号。

手机语音（App 1.1 起）是 `voice_message`：Hub 识别后把转写回传手机仅作显示，同时直接交给助理，并在上下文里标注 `userInputMode: voice`，由助理结合上下文理解；只有确实无法判断时才追问。识别不再按说话节奏回放（实测 7.6 秒语音 7.8→2.1 秒、26 秒语音 25→4.9 秒，文字相同，`scripts/phone-voice-speed-probe.js`）。旧 App 的 `voice`（识别后填入输入框）保留兼容；`profile` 等新类型只发给发过 `hello` 并声明能力的 App。

### 自答优先与换班（2026-10-03 第二轮）

助理的首要指标是保证质量下尽快答复：几步内能答完、不需大量阅读的事由助理直接回答；要长时间思考、写代码、做报告、深度分析或大量读写文件的才新建会话（一般 standard，开发与深度分析 deep，fast 只在用户要求单独开会话做简单事时用），让大段内容留在那个会话的上下文里。自己处理几步仍无结论就交出去。

助理是长寿会话，每轮读入的资料会累积（实测两轮短对话后上下文已约 4.3 万 token），回答随之变慢、旧内容也会干扰判断（Chroma「上下文腐化」研究：远未到上限就开始变差）。业界的「快满时压缩」（Claude Code 约 93%～95%、Codex ≤90%）只防溢出；OpenClaw 按天/空闲重开、重开前把要点写进记忆。我们的规则在 `core/hub-assistant/rotation.js`：

- 换班时机：空闲超过 2 小时，或跨过每天 4 点，且上下文已超过 3 万 token；或上下文到后端上限（Claude 15 万、其他 10 万，且不超过模型窗口一半）。
- 后台换班：每分钟检查一次，到点且助理空闲时，先让旧助理写不超过 300 字的交接（未办完的事、最近的决定与偏好、关注任务状态），记入交接记录「【上一班交接】」，再同档位新开会话；旧会话改名「（已换班）」休眠，可查看但没有会话管理权限。你回来时直接用新会话，不用等。
- 就绪时到点（例如 Hub 刚启动、后台还没轮到）直接换班，不写交接以免让这条消息多等，只靠原始交接记录接续。忙时绝不换班；新建失败恢复旧绑定。
- 手动：助理页「新开助理」按钮，同样先写交接再换班。
- 校准：每轮在 `assistant/turn-metrics.jsonl` 记「上下文 token、本轮用时、模型」，攒数据后再调上限。`HUB_ASSISTANT_ROTATE_TOKENS` 仅供实测压低上限，`ROUTER_ROTATE=1 node tests/e2e-assistant-router-live.js` 验证自答、换班与交接。

### 成长记忆与按需刷新（2026-10-04）

助理有两份由 Hub 保管、各后端共用的成长记忆（`assistant/memory/`）：`USER.md` 记田哥的偏好与习惯，`MEMORY.md` 记长期事实、约定与常用资料入口。写入只走 `update_memory` 工具（add 一句话 / remove 原文片段 / rewrite 整理），Hub 加本地日期与来源、限长（3000 / 6000 字，超了要求先合并）、拦截疑似密钥、每次改动备份到 `history/` 并记 `CHANGES.md`。成长时机：田哥说「记住」时当场写；换班交接前旧助理先把这一班发现的稳定偏好写进去；用户也可直接编辑（助理页「助理记忆」按钮）。读取：Claude 通过 `--append-system-prompt-file`（`assistant-system-prompt.md`）每轮生效，不占每轮 2048 字；Codex 等在新会话第一轮按提示读资料包里的 `assistantMemory`，之后全程遵守。为什么不只靠 CLAUDE.md / AGENTS.md：那是全局规则、所有会话共用、手工维护，交接记录又只带最近 12 条，长期偏好会在换班中丢失。

工作台按需刷新：2 秒定时器只检查关注任务的新回复（手机与助理页提醒靠它）；工作台在用户提问、助理按需查资料或打开工作档案时才重建。会话正文存档每会话只留最近 3 版，每轮资料包保留 7 天。

### 工作账本、事件驱动与每日复盘（2026-10-04 第二轮）

- 不做固定频率心跳：任一会话答完一轮由完成事件（Claude / Codex / Kimi / Claude 原生）立即记进工作账本 `assistant/ledger/`（`ledger.jsonl` + 按天 Markdown），被关注的任务立即提醒；助理答完一轮按「最后活动 + 2 小时」精确排换班检查，另有每天 4 点的定时；只有持有助理的 Hub 每 2 小时做一次全面核对补漏；被关注会话不发完成事件（千问、GLM 等）时才每 5 分钟补查关注任务。
- 不漏的保证：每个会话一个读取游标，只读新增；提问前先增量补齐（包括关掉的会话、群聊回答文件），资料包里的 `workLedger` 给出「上次助理真正读资料之后」记下的全部条目（按记账时间，不按答复时间）。闲聊不读资料，增量保留到下次；换班交接不算一次提问。只有原生文件或身份确实换了才重置游标，暂时状况保留游标；群聊读取被截断时不推进群聊水位线。账本保留 30 天，30 天无活动的会话清掉游标与去重表。账本是其他会话的原文，不能据此写记忆。
- 记忆的正本是 Hub 的 USER.md / MEMORY.md，所有当助理的模型共用；Claude Code 自动记忆与 Codex memories 只在各自 CLI 内自动生效，作为参考来源。助理会主动记下明确表态或反复体现的偏好（不必等「记住」）；当天首次换班做复盘：补记稳定偏好，并读上次复盘以来更新过的两家原生记忆（Claude 记忆目录中 type 为 user/feedback 的条目、Codex `memory_summary.md`），把与合作方式相关的同步进正本。凡不是田哥明说「记住」的写入都推送「我记下了：……」。复盘交接最长等 7 分钟，超时且旧助理仍在跑则本次不换班。

### 手机快速通道与长等待（2026-10-04 第三轮）

- 目标：天气、汇率、常识、闲聊这类简单问题，从手机松手到看到答复 5 秒内。实测约 2～3 秒（Hub 侧：识别约 1 秒 + 快速模型约 1 秒）。
- 快速通道 `core/hub-assistant/fast-lane.js`：手机发来的文字或语音转写，先过关键词判断（会话、任务、派工、文件、项目、记住等明显涉及工作的说法直接交给完整助理），再交给百炼 `qwen3.8-flash`（流式、关闭思考、强制联网搜索；不强制联网时实时数字会编造。最初用的 qwen-flash 不会把工作类问题交还、会自己编答案，已于同日换掉，可用 `HUB_ASSISTANT_FAST_LANE_MODEL` 覆盖）。调用凭据先用 Hub 已配置的阿里云 Token Plan 套餐 Key（`config.json` 的 `acp.apiKey`，只认官方套餐端点，走包月额度），套餐拒绝（额度用完、限流）时同一请求换语音设置里的百炼按量 Key。模型判断属于工作或 Hub 里的事时只输出交还标记，通道一看到标记就中止并交给完整助理。答复记入助理的近期对话（`recordFastLane`），后续提问能接上。出错或超时（6 秒）同样回退到完整助理。`HUB_ASSISTANT_FAST_LANE=0` 关闭。
- 收消息改长等待：中继 `/poll?wait=N`（≤20 秒）没有新消息就挂起，消息到达即返回；旧中继忽略参数、立即返回，Hub 与 App 都按「返回过快就退回定时间隔」兼容。Hub 收消息走独立循环 `receiveLoop`，处理由 `kick` 触发（新消息、助理答完一轮、关注提醒），定时器只做兜底；App 1.1.2 起前台长等待，发送走独立的 `flushOutbox`，不被挂起的接收阻塞。
- 限制：快速通道只用于手机路径；需要 Hub 资料的问题仍走 CLI 助理，约 10～15 秒。每次快速答复消耗一次百炼调用（含联网搜索）。

### 回答方式：快速回答（API）/ 助理会话（CLI）（2026-10-04 第四轮）

- 田哥确认：手机消息默认「快速回答」——API 前台（千问 3.8 Flash 或 DeepSeek V4.1 Flash）当场答简单问题；工作、Hub 状态、难题和「交给助理」的话转给专属助理会话。也可切到「助理会话」：每条都直接交给专属助理会话（默认 Claude Code Sonnet），由它自己研究或在 Hub 里新建会话。前台交出去的始终是这一个固定助理会话，不另起会话。
- 设置存在助理 store 的 `frontDesk`（`core/hub-assistant/front-desk.js` 负责选项、默认值与校验；旧的 `fastLaneDisabled` 视为 cli）。手机 `profile` 包带 `frontDesk` 选项表，手机发 `set_front_desk`（不排队，助理忙时也立即生效）；电脑助理工具栏有同一设置的下拉框，任一端修改都会重发 profile，两端同步。
- 手机 App 1.1.3「助理设置」：上为回答方式两张卡片与快答模型，下为助理会话的引擎、模型、思考深度，「保存」固定在底部。
