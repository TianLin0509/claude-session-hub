# 公司版「论坛」页（2026-10-18）

每天把公司内部两个社区（稼先社区、心声社区）的热门帖子同步到 Hub，附 AI 看点和每帖一句话摘要。只在公司版启用（`features.companyForum`），数据只留在这台电脑。

## 为什么用 Hub 自己的浏览器窗口取数

公司真机回执 Q-1018-01：

- 两站都是前端渲染的单页应用，内网单点登录记在浏览器里。`Invoke-WebRequest -UseDefaultCredentials` 只拿到空壳；数据接口直连时，稼先回 401，心声回「认证失败」。
- CodeAgent 自带的 `fetch_intranet` 用的是 Playwright 加一份登录过的 Chrome 资料。它固定等 5 秒取整页文字，同一页实测出现过一次 3122 字、一次 189 字两种结果。它只给纯文字，没有帖子编号，不适合每天无人值守地跑。

所以由 Hub 开隐藏窗口打开首页（`main/company-forum-browser.js`）：

- 用调试协议截下页面取数据的 JSON 响应。帖子编号、阅读数、回复数都在里面。
- 再收页面上的帖子链接，以及指定板块（「24小时点击排行」等）的文字。
- 等页面安定才收：正文长度连续两次不变，不按固定秒数。
- 登录状态存在独立分区 `persist:company-forum`，不碰用户的 Chrome / Edge，也不和 CodeAgent 的抓取工具抢同一份浏览器资料。
- 没登录时，用户点「登录」，弹出同一分区的可见窗口。回到站点、且页面不再是登录页连续 3 秒后，窗口自动关掉，并只重新同步这个站。
- 所有窗口都挂在一个永不显示的宿主下（同桌宠），这样 Windows 挑进程主窗口时不会挑到它们。

## 站点地址

代码里不写公司域名：公开库的泄露检查会拦，公司域名也不该进公开库。

- 两个站点是 `jx.<域名>` 和 `xinsheng.<域名>`。
- 域名默认取本人公司邮箱 @ 后面那段。这个邮箱助理页已经从 WeLink 账号读到，存在 `company-assistant/settings.json`。
- 设置里也能直接填。

站点的路径、接口与字段见 `core/company-forum/sites.js`，依据是公司回执 Q-1018-01 第 2 轮：

- 稼先热榜接口是 `jxhome/homeHotResources`（本周热榜，20 条），首页 `/?menuKey=hot` 就是热点页。
- 心声的两个排行在卡片接口 `cards/recommends/home/right` 的第 5、6 张卡片里，每条只有编号、标题、链接；阅读、回复数在详情接口里。
- 公司电脑上全新的浏览器也会经安全终端（SPES）免密自动登录，所以「登录」按钮只是兜底。

## 认帖子（`core/company-forum/extract.js`）

每个榜按下面的顺序取，前一种不到 3 条才换下一种：

1. 板块里的帖子链接；
2. 截到的 JSON 里「多数元素像帖子」的数组。挑网址最像这个榜的（例如稼先热榜看 `hot`）；同分时取后截到的，因为点了「热点」以后才取热榜；
3. 板块里的文字行，只有标题、没有链接；
4. 稼先退到整页的帖子链接。

接口里同一帖子（编号或标题对得上）的阅读、回复、时间用来补到第 1、3、4 种结果上。只有编号、没有链接的，按详情页格式补链接。字段名按常见写法多认几种。页面认不出帖子时，会把截到的接口路径和字段名存成本机诊断文件 `company-forum/diagnostic-<站>.json`，方便公司那边的 CodeAgent 对照。

## 摘要（`core/company-forum/summary.js`）

- 两站轮流挑排行靠前的帖子，默认 10 条。先读正文摘录，最多 3000 字；上次读过的不重读。
- 把挑出的帖子编成 P1…Pn 交给固定的 CodeAgent 会话（purpose=company-forum：不挂 Hub 的 MCP、不挂「问家里」，用默认模型），只依据标题和摘录写，只输出 JSON。
- 回来的看点和摘要必须指回真实编号，指不回的删掉并在页面上说明。摘要写坏了也不影响热帖列表。

## 定时

- 工作日 08:30（可改）同步一次。打开论坛页时当天还没同步，就当场同步；也可以手动「刷新」。
- 有站点没登录或没取到时，30 分钟后再试，每天最多 6 次。21:00 以后不自动跑。
- 历史留 7 天。
