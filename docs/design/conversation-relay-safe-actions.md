# 群聊接力：只读补救入口

2026-10-09，按田哥确认的 v2 最小改动原型实现。自定义工作流继续使用普通群聊的顺序发言，不引入任务校对、额外恢复模式或自动重试。

## 用户看到什么

- 正常回答沿用发言顺序和暂停按钮；用户主动暂停仍可继续。
- 收到 `submission_unknown` 时显示「接收或完成状态待确认」，默认不提供继续派发。
- 长时间没有结束确认只提示「状态可能过期」，不推断卡死、限流或未送达。
- 异常状态在原输入区提供「复制本轮 Prompt」和「打开对应成员 CLI」。未完成回答卡片也以查看 CLI、复制已有存档为默认操作。已完成回答在「更多」里的原有重发入口保留。
- 缺完整存档时隐藏复制入口；复制失败时展示只读原文，可以选中复制。
- 状态不明不把已派发的问题重新塞入输入框，不改动用户草稿。

## 行为边界

复制只使用对应工作流运行、步骤、成员和提交尝试的存档全文。运行中的待确认输入从持久记录取，结束后的输入从同一尝试的 `sourcePrompt` 取；原问题、补充要求、前序回答及写回路径均保留。不拿当前输入框或原问题单独代替全文。点击后重新读取并核对当前轮次，轮次已变化或存档缺失则明确报出。

查看 CLI 是显式切换到该成员的原生后台视图。它不调用发送、暂停、恢复或重启；已关闭的 CLI 如实提示不可查看，不自动唤醒写入进程。正常的卡片导航行为保持不变。文件路径识别跳过按钮和输入控件，避免成员名字被误识别为目录并抢走点击。

用户先看 CLI 确认实际状态。确实需要手动补发时，先用原有暂停入口暂停接力，再自行粘贴并发送。复制成功只说明剪贴板已核验，不证明提交成功，也不自动标记该成员完成或承诺接力自动恢复。

## 验证与防复发

相关单测检查成员、运行、轮次、步骤和尝试的精确匹配，包括重复成员和多人同轮；Claude、Codex、Gemini、Kimi 均使用同一只读 CLI 入口。

`node tests/e2e-relay-safe-actions-cdp.js` 在隔离 Electron 中点击真实工作流设置与输入框，使用受控原生 Provider 进程。先让 Codex 写回答并结束，再让 Claude 持续回答；注入迟到/待确认提示，检查复制与查看没有新增派发、没有修改后端运行状态、没有丢草稿；检查复制失败、缺存档、正常结束和窄窗口。390 像素窗口用既有会话栏折叠入口腾出正文宽度。测试剪贴板使用内存替身，不覆盖系统剪贴板。

`node tests/e2e-conversation-workflow-cdp.js` 回归空 Prompt、连续新输入、真实结束才接力、工作流开关、运行中关闭、暂停以及重开后的状态。两个 GUI 夹具在自己的临时助理数据库关闭每日秘书定时任务，避免它在测试期间向同一 Provider 收件日志派发无关任务；生产设置不变。

全量合并检查仍由 `scripts/merge_task.py` 执行。受控进程验证界面和协议边界，不等于本轮调用了四家真实模型；不宣称工作流在所有网络、额度和 CLI 版本组合下永远无 Bug。
