# 工具账号与共享登录 · 2026-09-27

源需求：以左侧「工具」目录为范围，盘点所有需要登录的 MCP、skill、插件，迁入账号页并共享登录。

## 账号来源

账号页集中展示每个工具实际依赖的账号。技能是调用方法，插件是包装；只改技能说明、只安装插件或只打开网站都不算接入成功。

- ChatGPT 网页生图与公司中转已有可回退的浏览器绑定事务。只有实际配置仍指向 Hub 入口时才显示已绑定；绑定不等于登录有效或任务可用。
- 网页圆桌的 DeepSeek、Kimi、千问使用 Hub 主身份。`web_status` 返回真实共享资料路径，不再显示废弃的各站独立目录。
- 通用 Playwright、语雀 Cookie 工具和社交采集器仍显示待迁移，保留各自数据，不能用一个绿色状态掩盖未实现的适配。
- 百炼、GitHub、行情、SFTP、R2 等协议使用密钥或原生授权。集中登记依赖、只读核对原生记录，不把密钥当成网页登录，也不复制到 Hub 明文文件。
- 客户端内置生图和内置浏览器使用宿主授权；没有本机共享 Chrome 接口时明确标注。

## 实现

`tool-account-catalog` 保存经核对的依赖关系；新工具没有映射时显示待核对，不从名称中的 login、API 等关键字猜测。插件从组件继承依赖。`tool-accounts` 将实际绑定和原生授权记录投影为不含秘密的状态。`capability-catalog` 补充 mcporter 入口，与账号页共用目录缓存。

账号页独立加载工具盘点，不阻塞原来的登录检查和进度；工具列表增加账号入口。这里不启动浏览器、不检查云端额度、不执行提示词、不恢复他人的任务。原始凭据内容不经过 IPC、日志或报告。

## 本轮边界

本模块提供集中盘点和明确的迁移缺口，不将尚未适配的外部工具标记为已迁移。生产生图/中转绑定仍须匹配主副身份；映射未知时不能猜测。合入前保持生产配置不变。真实任务成功另行留证，单测和隔离页面测试不替代真实账号验收。

## 2026-09-27 用户补充

- 生图必须保留两个登录组：primary → main、secondary → alt，每组原有四个工作页面不变。
- 公司中转使用 lintian0509。主资料目录的 Google 身份记录包含该邮箱，副目录不包含；按用户指定映射到 main，但该记录不能代替本次 ChatGPT 官网身份核验。
- AI 工具账号与外部服务分组。GitHub、语雀固定提供专属 Chrome 主账号入口，既有网页登录资料留在同一 profile。
- GitHub 工具授权直接复用官方 CLI 的系统密钥库；手动点击时无头检查，解析 JSON 中实际 state，不能仅以退出码 0 判成功。需要授权时打开官方设备授权流程，其网页入口固定到 Hub Chrome。页面展示上次检查时间。
- 语雀旧同步工具的 Cookie 调用暂未适配；网页登录入口已集中，工具仍标记待迁移。不能把它改绿来宣称所有工具已共享。
- 修复真实接入时发现的 Windows 空文件字节锁冲突：已有工作进程持锁时不写入锁文件，按原协议等待空闲；保留排队/暂停任务与旧登录资料。新增真实子进程持锁回归测试。
