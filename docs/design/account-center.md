# 账号与授权

侧栏第七个「权限」入口，目标是全局登录速览和快速打开正确账号的登录入口。没有活动会话也可打开。

## 页面与迁移

### 2026-09-21 权限页工作台

- 总览采用紧凑账号列表与用途详情，可切换卡片布局；需要处理与已登录可分别筛选。
- OpenAI 仍是平台入口，不能根据同平台或脱敏邮箱合并真实身份。各用途分别确认授权，当前浏览器资料尚未跨工具共用，界面明确说明。
- 已登录或尚未确认的网页连接优先提供「打开网页」，原生客户端保留「查看授权 / 登录账号」。重新登录、检查和配置在详情中。
- `accounts:open` 只打开已注册网页连接的原浏览器，不创建或释放登录等待锁、不保存新的登录结论、不请求短信。受管浏览器优先激活已存在的对应网站页面；生图 / 中转仍走原工具。
- 顶部「集中处理」汇集明确需要登录或已发起待验证的授权；未知、离线、工具不可用不自动计入。统计单位仍是可确认的授权连接（显式生图组去重），不能冒充已识别的真人账号数量。
- 集中处理支持官网窗口、验证码、检查、解除等待；Escape 只关闭最上层验证码或待办弹窗。手机号与验证码仍不持久化。
- 批量选择与手机号辅助位于列表下方。验证码提交后自动发起一次只读检查，只有真实检查确认才显示已登录；页面改变或验证尚未完成时保留未知，不能自动重发短信。
- 设计原型中的任意网站新账号新增、手机号偏好持久化、跨工具共享浏览器未在本次 UI 接入中实现，不提供模拟成功按钮或假配置。
- 网页圆桌恢复已接入（2026-09-22）：受阻任务按账号合并到「恢复任务 / 集中处理」，完成官方验证后点「检查并继续任务」。仅新鲜的明确登录证据触发子 MCP 恢复；已发送的问题只补收。已完成回答保留，原圆桌自动继续余下轮次与综合；取消过的任务不恢复。详情见 `web-roundtable-mcp.md`。

- 账号总览：按原生 Agent、网页、API、其他服务筛选；展示证据来源、检查时间、过期状态、用途、登录与检查按钮。
- 功能与账号：对应 Claude/Codex 会话、公司中转、网页生图等实际使用的连接。
- 默认只列主要账号：Claude/Codex、受管 AI 网页、公司中转和启用的生图账号。API、其他 CLI、监控等在「其他接入」查看；「全部」仍可查找所有连接。
- OpenAI 相关用途在总览收为一个默认折叠入口：Codex、ChatGPT 网页、生图和公司中转；展开后保留各身份、主/备用账号及各自的登录检查。平台分组不等于身份已确认相同，也不合并 CLI 凭据和浏览器档案。API Key 仍在其他接入中单独配置。
- OpenAI 入口支持一次勾选全部用途；批量登录沿用已有的逐授权检查和跳过逻辑，只提交原始连接 ID，不把一个用途的登录成功当作所有用途都已登录。勾选部分用途时分组复选框显示部分选中；搜索或从功能表查看账号可展开对应分组。
- 生图按原工具显式 `login_group` 合并展示，同一账号的多个并行浏览器只占一项；不根据名字后缀或脱敏邮箱猜测身份。原始连接和调度不变，详情可展开每个浏览器的登录/检查入口。启用成员中需要登录或状态未确认的成员优先代表该组，按钮和批量登录仍指向该成员的原始连接 ID；停用成员不触发主列表登录告警。
- 「功能与账号」每项用途只列一行，生图的主账号与备用账号在同一行呈现；辅助接入按需展开。旧队列没有 `login_group` 时保留独立记录。
- 活动记录：操作结果，不保存密码、验证码、Cookie 或密钥。账号身份脱敏。
- 接入配置：从设置迁移 Claude/Codex/Gemini/Kimi/DeepSeek 面板、Codex 默认账号和 CODEX_HOME、API 密钥及服务器 Bearer Token。继续使用既有配置格式，无凭据复制或搬家。
- 设置保留代理、监控地址与开关、通知接收对象、聊天外观。两处只提交各自字段，避免旧表单覆盖另一处的凭据。
- 新默认接入配置只影响新会话；不改变运行中会话身份。页面覆盖层保留普通会话与群聊成员双屏、草稿。

## 状态与账号来源

| 连接 | 状态来源 | 登录入口 |
| --- | --- | --- |
| Claude Code | `claude auth status --json` | 原 CLI `auth login` |
| Codex 订阅账号 | 对应 CODEX_HOME 的 `codex login status` | 同一 CODEX_HOME 的原生 `login` |
| Gemini CLI | 本机 OAuth 记录，仅显示已配置 | 官方 CLI |
| Kimi Code | 官方用量接口成功回执 | `kimi login` |
| DeepSeek / 豆包 / Kimi / 千问 / Gemini / ChatGPT 网页 | 专用浏览器当前页面的明确账号入口 | Chrome/Edge 官方页面 |
| ChatGPT 生图 | 原共享队列的显式登录检查回执 | 原账号队列 `open` 控制命令 |
| 公司中转 | 原中转浏览器可见登录状态 | 原工具 `open_login` |
| Codex Web GPT | 服务健康，只表示工具在线 | 原固定隔离启动器 |
| 百炼 Token Plan | 官方 CLI 用量接口回执 | `bl auth login --console` |
| 飞书 | CLI 本机用户授权状态；通知机器人配置单独说明 | 通知配置选定的官方 CLI |
| API / 监控 Token | 配置存在性，不能证明有效性 | 账号接入配置 |

原生 CLI 证明的是当前本机凭据状态，不保证远端会话、额度或功能成功。五分钟以上的回执明确标记上次状态。网络/工具失败显示未确认，不冒充退出登录。Gemini CLI 与网页授权、Codex 与 ChatGPT 网页授权保持独立。

## 持久化与执行边界

- Gemini 网页的 Google 登录使用普通 Chrome/Edge 可见窗口，不附带远程调试、headless 或自动化参数，不自动输入 Google 密码/验证码。复用原 `account-browsers/gemini`；不复制 Cookie、不修改浏览器指纹。旧受控窗口仍打开时提示先关闭，不能把新普通窗口交给旧受控进程。
- 手动 Google 登录窗口运行期间，“检查登录”显示待人工完成，不附着、不关闭窗口。用户完成并关闭该网站全部专用窗口后，“检查登录”才以同一 profile 启动临时只读检查；发现 Google 登录跳转即交还用户，不自动提交认证表单。仅真实账号入口证据算已登录，临时检查结束关闭自己启动的浏览器。
- 普通登录窗口、只读检查与 MCP 使用相同显式数据目录的浏览器互斥锁；进程检查按完整 profile 路径精确匹配，不按路径前缀或个人 Chrome 推断归属。进程采集失败不能当作窗口已关闭。

- 受管网页目录：Hub 数据目录 `account-browsers/<provider>`，浏览器原生管理 Cookie 与登录信息。关闭后保留；不承诺永久免登录。
- 中转、生图、Codex Web GPT 继续使用原工具目录，不复制或合并现有用户 profile。
- 登录期间打开官方可见窗口；DeepSeek、豆包支持批量填写手机号、申请短信和按站点提交验证码。其他站点在官方窗口继续。扫码、人机验证由本人完成；网页圆桌在检查通过后按原任务的发送边界恢复，其他工具仍使用原来的恢复流程。
- `account-center` 目录只保存脱敏观测、活动记录和跨 Hub 登录等待文件。同一账号重复点击不重复启动；失败释放，确认登录后解除等待。用户关闭窗口后可手动解除等待；不会关闭浏览器或退出账号。
- 原生检查有一分钟缓存；打开页面时只自动检查 Claude/Codex。网页不自动发送提示词，不主动开启登录窗口。
- 生图检查进入原持久队列，排队不等于已检查；页面继续读取最终回执。查看公司中转登录状态不调用会初始化拉取游标的 `status()`。
- 适配器只接受固定连接与命令。官方网页只连 loopback CDP，校验 provider 主机，不能把游客输入框当登录证据。
- `CLAUDE_HUB_HOME_DIR` 隔离实例禁用真实外部工具；账号子进程 fixture 仅在隔离模式生效。

## 验证入口

### 批量登录

- 总览支持逐项勾选、全选当前筛选列表、选择需要登录的账号；最多选择 24 个连接，同时发起 3 个。先检查并跳过有效登录，再沿用每个工具自己的登录入口和浏览器目录。
- `accounts:login-many` 只接受已注册连接，整批验证通过才启动。沿用跨 Hub 单账号登录等待锁；同一账号重复请求不重复打开，也不重复申请短信。
- 手机号仅在本批内存中使用，发起后清空输入框；验证码只提交到所选站点，立即清空输入框，不进入状态、活动记录或配置文件。浏览器会按官网自身规则保存登录状态和表单数据。
- DeepSeek、豆包适配器采用官网实测 DOM；遇到人机验证、页面变化或结果不明，交回官方窗口，不自动重试短信。Kimi、千问、Google 和 ChatGPT 目前保留官方窗口流程。
- 点击验证码提交不代表已登录，必须另行检查官网账号入口。批次进度只保存在当前 Hub 内存；重启后保留原浏览器登录信息与账号状态记录。
- 页面刷新时避开手机号、搜索和验证码输入，避免定时重绘中断用户输入。

- `node --test tests/unit-account-center.test.js`
- `node tests/e2e-account-center-cdp.js`：真实隔离 Electron、鼠标输入、IPC、账号子进程夹具、配置落盘、普通/群聊双屏草稿、与记忆页互斥、窄窗口截图。夹具不是真实短信或网站登录 E2E。
- `node scripts/run_unit_tests.js`：全量单元测试。Windows 环境需要 Git `bin` 中的 `sh.exe` 位于 PATH，开发流程旧测试会调用它。
