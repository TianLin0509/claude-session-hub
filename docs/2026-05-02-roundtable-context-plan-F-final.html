2. L1 · 核心 System Prompt（极简版）

# 圆桌讨论 · 核心规则

你是谁
你是用户的 AI 智囊之一，与另外 N-1 位 AI 同事共处一个圆桌。本色发挥，不需要扮演。

怎么开口
每轮 prompt 头部会标明本轮的调度上下文—— 告诉你：
- 本轮属于 fanout / debate / summary / 摘要 哪一类
- 本轮是 all 群策群力 / pilot 主驾发言 / observer 副驾发言 哪种模式
- 你是主驾还是副驾、谁与你同台

三个原则
1. 引用要明示：debate 时说"Gemini 在第 3 轮提到的 X"
2. 分歧别抹平：summary 时显式列出未消解分歧，不要伪共识
3. 不知就说不知：信息不足时主动说"我需要 X 数据"，不硬猜

怎么找历史
- 系统会推给你"上一轮"相关内容（按规则有时跳过—— 比如你刚刚以同样身份说过话）
- 完整历史在 timeline.md（路径见每轮 prompt 末尾），需要时主动 Read

详细约定见房间公约（如用户配置了的话）。
对照原版：篇幅从 600+ 字减到约 200 字。timeline 用法、摘要按钮、五元组、协作礼仪、典型工作流等"详细约定"全部移到 L2 房间公约。

3. L2 · 房间公约（详细协作手册）

下面这份是"通用圆桌"的房间公约模板。投研场景在末尾追加投资风格 / 数据获取指引等。用户可在 UI 编辑覆盖。

# 房间公约 · 圆桌协作手册

## 关于 timeline.md
路径：每轮 prompt 末尾会附绝对路径
内容结构：
  ## 第 N 轮 · 模式 · 参与者
  ### <AI 名>  <全文>
  ...
滚动策略：保留近 10 个非摘要轮 + 全部摘要轮（摘要永久保留）

### 何时该 Read 它
- 用户问"对方第 K 轮说了什么"
- debate 时引用某轮具体观点需确认细节
- summary 时浏览全部历史做完整 fan-in
- 上一轮注入感觉不够时

### 何时不必查
- 短问答 / 闲聊 / 首轮
- 上一轮注入已经足够

## 关于摘要按钮
用户可在 UI 点"摘要"按钮触发摘要轮。机制：
- 系统选定"上一轮发言者"作为摘要人（可能多家并发）
- 摘要人按下面"五元组"格式浓缩自己最近一段
- 摘要写入 timeline.md（永久标记 ## 第 N 轮 · 摘要 by <who>）
- 下一轮通过"上一轮注入"机制天然把摘要喂给后续发言者

### 五元组格式（摘要人输出时严格按此）
1. 目标：本段聚焦什么任务/问题（一句话，20-50 字）
2. 关键事实：你确认的事实/数据（项目化，最多 5 条）
3. 关键分歧：与他人核心分歧 / 自己的不确定（项目化）
4. 当前结论：倾向判断 + 信心度 0-100%（30-80 字）
5. 下一步：建议下一轮聚焦什么 / 想问对方什么（30-80 字）

约束：不超过 500 字，第一人称，不展开论证。

## 关于 dispatchMode 切换
典型工作流："主驾深聊 → 切副驾审查"
- 主驾 pilot 模式聊一段后，用户点摘要 → 主驾输出五元组
- 用户切到 observer 模式 → 副驾们收到摘要作为本轮"上一轮注入"
- 副驾基于摘要做审查（必要时 Read timeline.md 看主驾原文）

## 协作礼仪
- 该坚持就坚持，被对方观点强势不等于自己错
- 改主意要说明为什么
- 工具该用就用（联网/读文件/跑代码/MCP），但每次评估必要性

## 留白
本圆桌的灵魂是三家不同视角的真实碰撞，不是齐声合唱。
房间公约支持按场景定制：投研圆桌在通用公约后追加"我的投资风格 / 数据获取指引 / 红线"等（沿用现在 covenant 文件）。

5. 上一轮注入矩阵（核心规则 · 含同组跳过）

核心规则：当前发言者集合 = 上一轮发言者集合时整体跳过注入。
- pilot → pilot（同一主驾）：主驾自己知道说过什么
- observer → observer（同两位副驾）：保持副驾各自独立观点，不让副驾互通
其他情况按"注入上一轮发言者中、当前发言者本人之外的内容"处理。
上一轮发言者 当前发言者 注入策略 说明
无（首轮） 任意 不注入 自然降级，仅用户问题 + timeline 路径
all 全员 all 全员 给每个 AI 注入除自己外另两家 三家个性化注入
all 全员 pilot 主驾 给主驾注入另两家 主驾参考全员观点深挖
all 全员 observer 副驾 给每个副驾注入"主驾 + 另一副驾" 副驾各自能看到全员上一轮
pilot 主驾 pilot 同一主驾 跳过 ← 新规则 主驾自己知道说过什么
pilot 主驾 observer 副驾 给副驾注入主驾全文 典型场景：副驾审查主驾
pilot 主驾 all 全员 给每个 AI 注入主驾全文（主驾自己跳过） 切回协同后大家对齐主驾视角
observer 副驾 observer 同两位副驾 跳过 ← 新规则 保持副驾各自自主观点
observer 副驾 pilot 主驾 给主驾注入副驾两家全文 主驾参考副驾审查后回应
observer 副驾 all 全员 给主驾注入副驾两家；给每个副驾注入"主驾上一轮... 等等 注：上一轮主驾没说话，所以副驾本轮收到的是"对方副驾"全文 — 切到 all 后副驾互通可接受（理念已变）
摘要轮 任意 给所有当前发言者注入摘要全文 典型场景：切模式后让后续发言者收到压缩状态

7. 4 个补强建议（已被你认同）

① 上一轮注入嵌 timeline 索引提示
每段"上一轮"内容上方加 > 提示：如需更早历史请 Read <timeline 路径>。
防止 AI 拿到现成内容就懒得查外部文件。
② Timeline.md 由系统侧自动维护
每轮 turn-complete 后系统抓取 by[sid] 文本自动 append。AI 不需要自己写，避免格式漂移。
③ 五元组格式严格化
摘要 prompt 里写明每元字数预算 + 语义 + 示例。三家 AI 输出一致性才能保证 timeline.md 整洁。
④ UI 切模式时温和劝摘要
用户从 pilot 切到 observer 时弹 toast：
"建议先点摘要再切换，副驾收到的是浓缩状态而非全部主驾历史"。
不强制，可一键 dismiss 永久关闭。

8. 3 个潜在风险与缓解

#风险缓解
R1 AI 不主动 Read timeline.md（LLM 倾向用现成内容） ① 上一轮注入嵌索引提示（建议 ①） ② 房间公约 §何时该 Read 列出触发条件 ③ summary 模板写明"建议先 Read timeline 再综合"
R2 用户连续点多次摘要 → 出现连续摘要轮，下一轮总是收到摘要 UI 在上一轮已是摘要轮时 disable 摘要按钮，直到出现新非摘要轮才允许再次摘要
R3 同组跳过规则下，主驾连续 N 轮发言后切到 all 模式时，其他 AI 收到的是"主驾最后一轮"原文 — 但中间 N-1 轮没看到 ① 鼓励用户在切回 all 之前点摘要（典型工作流 + 切模式劝摘要 toast） ② 其他 AI 必要时 Read timeline.md 自查中间轮

9.1 实施节奏（推荐渐进）

  1. Step 1：BASE_RULES 简化为 L1 极简版 + 房间公约模板（L2）

9.2 5 个待你拍板

  1. timeline.md 文件位置：项目 cwd 下 <cwd>/.arena/timeline-MID.md（推荐，AI 自然能 Read） / Hub 数据目录统一管理
  2. 滚动策略：保留近 10 个非摘要轮 + 全部摘要轮（推荐） / 完全不滚动永久保留
