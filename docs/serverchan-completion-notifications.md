# AI Hub 回答完成微信通知（Server酱）

AI Hub 可以在普通 session 回答完成、或群聊整轮全部收敛后，通过 Server酱向微信推送一条通知。

## 首次启用

1. 打开 Server酱官网，用微信完成登录并关注其服务号。
2. 在 Server酱后台复制 `SendKey`。
3. 点击普通 session 顶栏里“卡片 / PTY”左侧的“通知未配”，Hub 会直接打开“回答完成通知”设置。
4. 粘贴 `SendKey`，先点“发送测试”。微信收到测试消息后，再勾选“微信通知总开关”并保存。

生产 Hub 不需要重装依赖。保存配置后，新的完成事件会立即读取最新通知设置。

## 总开关语义

- 顶栏显示“通知开”：每次普通 session 回答完成都会推送，不判断窗口焦点、电脑空闲或任务耗时。
- 顶栏显示“通知关”：完成事件完全不推送。
- 顶栏显示“通知未配”：尚无有效 SendKey；点击会直接进入设置。
- 普通 session 每轮最多推送一条。
- 群聊成员不会逐个推送；整轮所有目标成员收敛后只推送一条汇总。
- 被新问题抢占或被用户中断的群聊轮次不推送。
- 默认不包含回复正文，只包含会话名、AI 类型、耗时和完成时间。
- “附带回复预览”由用户显式开启；开启后，预览内容会发送给 Server酱。
- 网络超时、HTTP 408/429/5xx 会按 2 秒、10 秒、60 秒退避重试。

## 隐私与本机数据

- `SendKey` 在设置界面使用密码框显示。
- `SendKey` 保存在 Hub 本机数据目录的 `config.json`，与现有 AI API Key 使用同一配置存储边界；不要分享该文件。
- 投递审计位于 Hub 数据目录的 `notification-delivery.jsonl`。
- 审计只记录事件哈希、发送状态、尝试次数和安全错误码，不记录 SendKey、通知标题、回答正文或预览。

也可以通过环境变量 `HUB_NOTIFY_SERVERCHAN_SENDKEY` 提供 SendKey；`HUB_NOTIFY_ENABLED=1` 可同时启用通知。环境变量优先于本机配置文件。

## 常见问题

- “请先粘贴有效的 SendKey”：SendKey 为空、过短，或包含空格和路径分隔符。
- “Server酱拒绝了请求”：检查 SendKey 是否复制完整，以及 Server酱账号的当日推送额度。
- “连接超时 / 无法连接”：检查本机网络、防火墙及 DNS；Server酱请求由 Electron 主进程直接发出。
- 没有收到某次通知：先确认顶栏是“通知开”，再用设置里的“发送测试”区分是完成事件问题还是 Server酱/微信链路问题。
