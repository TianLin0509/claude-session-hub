1. 背景与现状

1.1 现状盘点

LinDangAgent（C:\LinDangAgent）已经重构为纯轻量数据层，统一入口 python data_query.py <op>，共 19 个 op，全部围绕"单股查询"：

类别数量op 清单
单股字段13gate · basic · price · financial · flow · dragon-tiger · valuation · northbound · margin · peers · holders · pledge · funds
QMT 实时4qmt-kline · qmt-realtime · qmt-sector · qmt-financial
技术指标1indicators（17 项 RSI/MACD/Bollinger/...）
一键综合1snapshot（gate + basic + price_summary + indicators + flow）

Hub 圆桌（core/research-mcp-server.js）把这 19 个 op 压成仅 2 个 MCP 工具暴露给参与 AI：

fetch_lindang_stock(symbol)              → 调 snapshot
fetch_lindang_field(op, symbol, ...)     → op 是 18 个值的 enum

调用链：AI 工具调用 → MCP server → HTTP POST → Hub hookServer → core/lindang-bridge.js → spawn python data_query.py，5 层数据源兜底（tushare→akshare→东财→baostock→sina）已内建。

1.2 现状毛病

  • 工具粒度过粗：fetch_lindang_field 一个工具吞 18 个 op 的 enum，AI 选 op 容易迷糊，schema 表达能力弱（参数说明全挤在一个 description 字符串里）。
  • 信息维度缺口：研报、新闻、公告这三块 LinDangAgent 完全没接。投研深挖单股没研报/新闻几乎不可能形成完整判断。
  • 没有"信息时效"概念：AI 拿不准"我应该看哪些字段"——基本面是慢变（季度更新）、行情是实时、新闻是分钟级，全混在一起。
  • snapshot 信息密度有限：只覆盖 gate+basic+price+indicators+flow 5 个域，研报/股东/财报不在其中，需要 AI 多次单独调。

2. 目标

主要场景：投研 AI 群聊深挖单只个股（基础设定：用户抛一只股，群聊里 3-5 个 AI 围绕它讨论买/不买、技术面/估值/风险）。

MCP 设计原则：

  • 快 — AI 拿到信息的 round trip 越少越好（理想：3 次工具调用拿全景）
  • 稳 — 数据源失败有兜底，工具返回 schema 稳定（AI 不需要写 if/else 处理边界）
  • 准 — 工具按 AI 心智模型切分（"我要看慢变 / 实时 / 消息面"），AI 一眼能选对
  • 覆盖完整 — 行情/基本面/技术指标/资金/股东/研报/新闻/公告 8 大维度全覆盖

3. 方案 C 总览

按信息时效把 19 个旧 op + 3 个新 op 切成 3 个 MCP 工具：

4. stock_static 工具设计

输入 schema

{
  "name": "stock_static",
  "description": "拉 A 股单股的【慢变维度】信息：闸门(gate)、基本面(basic)、财报摘要(financial)、估值分位(valuation)、同行对比(peers)、大股东(holders)、股权质押(pledge)、基金持仓(funds)、券商研报(research)。一年内变化有限的画像类数据。AI 第一次接触某只股时优先调此工具。",
  "inputSchema": {
    "type": "object",
    "properties": {
      "symbol": {
        "type": "string",
        "description": "A股代码或名称（600519 / 600519.SH / 贵州茅台 都可）"
      },
      "fields": {
        "type": "array",
        "items": {
          "enum": ["gate","basic","financial","valuation","peers",
                  "holders","pledge","funds","research"]
        },
        "description": "可选；不传则返回精要（gate + basic + financial 摘要 + valuation 当前分位 + research 最近3条）。传具体子集则只返回这些字段的详细数据。"
      }
    },
    "required": ["symbol"]
  }
}

~1.5KB markdown 文本块，覆盖最常用的"我要快速了解这家公司"信息：

新增 3 个 facade 函数，内部并发调多个 data_query.py 子进程并合并结果：

  const results = await Promise.all(
    wanted.map(op => _runDataQuery(opMap[op], [symbol]))
  );
  return mergeStaticResults(symbol, results);
}

9. AI 使用纪律（替换现有 AGENT_GUIDE.md 圆桌章节）

圆桌标准开场（深挖单股）

AI 收到"分析 XX 股票"任务时，第一轮并行调（或顺序也行）3 个工具：

stock_static("600519")     # 拿公司画像（基本面、财报、研报）
stock_market("600519")     # 拿行情画像（走势、指标、资金）
stock_news("600519")       # 拿消息面画像（新闻、公告）

总耗时 5-15 秒，覆盖 8 大维度。第二轮需要深挖某块时再 fields=[...] 取详细。

场景推荐调用
第一次接触某股并行 stock_static + stock_market + stock_news
讨论"买不买"同上 + 第二轮深挖 stock_static(fields=["valuation","research"])
看技术面/形态stock_market(fields=["indicators","price"], days=120)
看是否有催化剂stock_news(days_back=30)
看机构态度stock_static(fields=["research","holders","funds"])
看主力资金stock_market(fields=["flow","dragon-tiger","northbound","margin"])

11. 风险与取舍

已识别风险

  • 每次调用 token 量上升：旧 fetch_lindang_field 一次拉 1 个 op，返回 ~1-3KB；新 stock_static 默认精要拉 9 个 op 合并，可能 5-10KB。缓解：精要文本严格控制在 1.5-2KB；详细数据走 fields 参数按需。
  • 并发调底层 op 可能触发 rate limit：tushare 单 token 每分钟有调用上限。缓解：bridge 内部加 throttle/串行 fallback；rate limit 异常时降级为顺序调。
  • 研报/新闻数据源稳定性低于 tushare：akshare/东财接口偶有改版或限流；公告爬虫易被反爬。缓解：3 层兜底（akshare→巨潮→交易所）；fetch_warnings 字段告知 AI"这次走的是兜底"。
  • QMT 实时数据要求 QMT 客户端启动：qmt-realtime/qmt-kline 在 fields 里时，若 QMT 未启动会失败。缓解：默认精要不包含 QMT，只在显式 fields=["qmt-realtime"] 时调，失败时返回非阻塞 warning。
  • 新工具 + 旧工具并存期 AI 困惑：MCP tools/list 同时返回 5 个工具可能让某些模型选错。缓解：旧工具 description 加 "[已弃用，请用 stock_static/market/news]" 前缀。

11.1 主动放弃的能力（YAGNI）

  • 跨股对比工具：不做"传入多个 symbol 一次返回"——AI 用 stock_static 调 N 次即可，复杂度不值得
  • 选股/筛选/排序：用户已确认主场景是"单股深挖"，不做量化筛选器
  • 板块/概念龙头：现状 qmt-sector 已存在但不在新 3 工具里，暂保留为单独 op，未来如需再补一个 sector_overview 工具
  • 笔记/记忆/写入工具：本规划只覆盖"读"，写入由 Hub 现有 memory 系统负责
