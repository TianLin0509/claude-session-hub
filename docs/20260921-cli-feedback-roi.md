## 方案审核（当前 agent 分三遍检查，并非多模型评审）

| 视角 | 评分 | 问题与处理 |
| --- | --- | --- |
| 架构 | 8/10 | 原方案统一活动总线偏大。现有原生内存快照、增量挂卡、后台原文可复用，优先窄改。 |

三视角共识：不新增高频全历史轮询、不以静默推断失败或健康、不自动重发；这是实施约束。两视角提出：将完整输出和小量实时预览分离，避免大日志复制。无须用户额外拍板的方案分歧。

## ROI 排序

1. 高：两家原生卡片走低延迟的当前轮内存刷新，仍单请求在途、合并更新、隐藏时暂停。
2. 高：输入卡保留简短提交回执，区分本地收到、排队、引擎收到、未确认；相同文字不同提交不串状态。
3. 高：卡片输入区与后台显示最近真实内容更新时间，静默仅提示等待，审批和停止优先。
4. 高：Codex 命令输出片段更新卡片有界预览，完整原文继续保留于后台来源。
5. 高：每 3 秒至多一个只读 Main 应答探测，显示 Hub 本地应答；与 agent 内容时间分开，不推断远端健康。隐藏或没有活跃任务时不发探测。
6. 暂缓：独立整机看门狗、全量事件总线重构、无法证实支持的 Claude 新事件；成本与回归面较大，先交付以上闭环。

本轮性能比较使用相同协议夹具和真实隔离 Electron；不更换生产模型或推理档。夹具测量仅证明本地反馈链路，不等于供应商响应速度或生产故障已复现。
