Claude Session Hub / 圆桌备用线路方案
日期：2026-05-01 原则：不影响当前正常 Hub 状态：决策稿

把 PackyAPI 接成备用线路，而不是替换当前主线路

推荐采用“默认不启用 + 显式选择 + 隔离配置目录 + 可一键回退”的接入方式。 当前 Claude Max / Codex / Gemini 的正常使用路径保持原样；Packy 只在用户主动选择、诊断通过、或某家模型失败后手动切换时参与。

默认行为 新建圆桌仍按当前官方线路启动，不自动改全局 CLI 配置。
备用入口 在每个 AI slot 增加“线路”选择：官方 / Packy 备用。
故障处置 卡片出错后显示“用 Packy 重启此家”，而不是后台偷偷切换。

硬闸门

  • 不改用户主目录现有 .claude / .codex / .gemini 配置。
  • 不把 Packy token 写入项目仓库，不进入 state/timeline 明文。
  • 不在已有 session 上热替换 provider；只对新建或重启的子会话生效。
  • 不自动接管 Claude 官方线路，Claude Max 当前工作流优先保留。
建议结论：先做诊断与手动备用，后做自动策略

产品形态

用户能看到什么变化

1. 设置页增加“备用线路”

把 Packy API Key 按 Claude / Codex / Gemini 分开填写，并显示分组提示，避免把 CC token 用到 Codex。

低风险 不影响默认启动

2. 新建圆桌 slot 可选线路

每个 slot 除了 AI 与模型，再多一个 Route：官方线路、Packy 备用、跟随默认。默认值仍是官方。

用户可控 需要 UI 小改

3. 故障卡片提供切换按钮

当 Gemini 429、Codex 退出、Claude 连接失败时，卡片给出“用 Packy 重启此家”，并保留原失败证据。

体感明显 需 watcher 配合

机制分层

从“完全隔离”到“策略路由”逐步推进

1

配置存储

在 Hub 自己的 config.json 下保存 Packy 备用线路配置，key 脱敏展示。

2

诊断验证

Hub Doctor 检查 base URL、CLI 可执行、token 分组、模型是否可用。

3

隔离启动

新建 Packy session 时使用隔离配置目录或临时 env，不写用户官方配置。

4

圆桌卡片

显示当前线路、耗时、错误原因，并提供手动切换重启。

5

策略路由

稳定后再允许“失败后建议切换”或“连续失败自动建议”，不做静默自动切换。

实现方案

尽量沿用现有 Hub 架构

推荐接入点

core/hub-config.js 扩展 Packy 配置读取；core/session-manager.js 根据 route profile 注入启动环境；renderer/meeting-create-modal.js 增加线路选择。

main.js::_addMeetingSubInternal() 已经把 slot 的 kind/model 传给 session manager，后续只需把 route 一起传下去。

配置隔离策略

Claude 类 CLI 使用 CLAUDE_CONFIG_DIR=.claude-hub-packy；Codex 优先评估是否支持 env/config override，否则使用 Hub 管控的隔离 CODEX_HOME；Gemini 使用 session env 注入 GOOGLE_GEMINI_BASE_URL。

如果某 CLI 不支持无污染注入，就先不纳入自动启动，只保留诊断提示。

风险与闸门

每个风险都要有可验证的拦截点

污染当前 CLI 配置最高优先级风险
禁止写用户主配置；所有 Packy profile 只写 Hub 数据目录或隔离 config dir。
必须有测试 启动 Packy 后校验主 .claude/settings.json、.codex/config.toml 未被改写。
令牌分组配错Packy 文档强调点
UI 上按 Claude / Codex / Gemini 分开填写，并显示“该 token 应来自哪个分组”。
Doctor 检查 模型不存在、鉴权失败时直接提示可能是分组错误。
静默切换导致结论不可解释圆桌审计风险
失败后只“建议切换”，用户点击后再重启；timeline 记录线路、模型、失败原因。
可审计 每轮卡片显示 Route Badge，例如 官方 / Packy。
Packy 稳定性未知外部服务风险
先做小样本延迟与成功率记录，按 Claude / Codex / Gemini 分开统计。
灰度 先只支持手动 Packy slot，不做默认 fallback。

阶段计划

建议按可回退的小步交付

P0：只做诊断

目标：不改变任何启动行为

新增 Packy 配置读取、脱敏展示、CLI 连通测试、模型测试。交付后用户能判断 Packy 是否值得接。

最安全

P1：手动备用线路

目标：新建 session 时显式选择

新建圆桌 slot 支持 Route 字段。只有选 Packy 的 slot 才注入 Packy 配置，默认 slot 完全不变。

推荐首个可用版本

P2：故障后一键切换

目标：降低卡死和 429 的用户成本

某家失败后，在卡片上提供“用 Packy 重启此家”。保留失败证据，重启后作为新 sid 继续参与后续轮次。

需 E2E 验证

验收标准

说“完成”前必须拿到这些证据

功能验收

官方线路默认启动成功；Packy 线路手动启动成功；失败后切换不会破坏原会话；timeline 能看到 route/model/error。

安全验收

主配置文件未变；API Key 不出现在日志、state、timeline、截图；Packy disabled 时所有行为与当前版本一致。
