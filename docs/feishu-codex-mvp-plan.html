Phase 1 MVP · 普通 Codex Session 先接飞书

先把手机变成 Codex 的远程输入、进度和审批面板

第一阶段不直接做圆桌，也不复活 PWA。目标是打通最短闭环： 飞书里新建一个 Codex session，Hub 在电脑端执行，手机收到进度、摘要和审批卡。 这条链路跑稳后，再把同样机制扩展到 Claude、Gemini 和圆桌。

为什么 MVP 先选普通 Codex session
链路最短 单 session 只有一个输入流和一个输出流，容易验证飞书事件、Hub 写入、回推和重连。
价值明确 手机上最常见需求是补一句、看进度、批工具调用，不需要一开始就完整复刻桌面。
可平滑升级 圆桌本质是多个 session 的编排。单 session 通了，圆桌只是多一层 orchestrator 和观点卡。
1

飞书建任务

输入“新建 codex：任务描述”，Hub 创建 Codex session 并绑定飞书 thread。

2

手机继续聊

同一个飞书 thread 后续消息直接写入该 session，形成远程连续对话。

3

卡片回推

Hub 不刷完整终端，而是推送开始、执行中、等待审批、完成摘要和失败原因。

4

再扩圆桌

复用同一套 channel gateway，把一个 Codex session 扩为多模型会议室。

MVP 功能清单

P0 必做

新建 Codex Session

飞书输入“新建 codex：任务”，Hub 创建 Codex session，记录 sessionId、飞书 chatId、message/threadId 和 cwd。

P0 必做

连续输入转发

同一个飞书 thread 后续普通消息自动写入绑定 session，支持补充说明、纠偏、继续执行。

P0 必做

状态卡回推

用卡片展示运行中、等待输入、等待审批、已完成、失败。避免把完整终端流刷满飞书。

P0 必做

工具审批卡

把命令、路径、工作目录和风险摘要发到飞书，提供允许一次、拒绝、只读允许等按钮。

P1 增强

最近输出摘要

输入“最近输出”返回最近若干行和一段摘要，解决手机端看长终端不舒服的问题。

P1 增强

任务控制命令

支持“状态”“停止”“继续”“重试”“保存摘要”，形成手机远程盯进度的常用控制面板。

P1 增强

任务完成总结

Codex 停止输出或任务完成时，飞书收到最终摘要、改动文件、验证结果和下一步建议。

P2 后续

Claude / Gemini 普通会话

复用同一套飞书 channel，把 provider 从 Codex 扩展到 Claude、Gemini，但仍保持单 session 语义。

P2 后续

圆桌入口

当单 session 的输入、输出、审批、状态都稳定后，再做“新建圆桌：问题”和多 AI 观点卡。

后端链路

飞书消息 用户私聊或群聊发送“新建 codex：...”以及后续追问。
Feishu Adapter 接收事件、校验来源、发送文本/卡片、处理按钮回调。
Hub Router 解析命令，找到或创建 session/thread 绑定。
Session Manager 创建 Codex session，写入输入，监听输出和工具请求。
飞书卡片 回推状态、审批、摘要和完成结果。
