3. 三个 MCP 工具详解

stock_static
慢变维度 · 9 域聚合

公司画像类信息。AI 第一次接触某只股优先调。一年内变化有限。

覆盖：
  • gate（退市/ST 闸门）
  • basic（PE/PB/市值/换手率）
  • financial（财报摘要）
  • valuation（PE/PB 历史分位）
  • peers（同业对比，含 akshare/THS 兜底）
  • holders（大股东）
  • pledge（股权质押）
  • funds（基金持仓）
  • research（券商研报🆕）
stock_market
实时维度 · 6 域聚合

行情和资金行为。讨论买卖时机、技术形态、资金动向时调。

覆盖：
  • price（K线+摘要，含 Ashare 救场）
  • indicators（17 项技术指标）
  • flow（主力净流入）
  • dragon-tiger（龙虎榜）
  • northbound（北向持股）
  • margin（融资融券）
stock_news
消息面 · 2 域聚合 🆕

突发事件和定期披露。讨论催化剂、重大事项时调。

覆盖：
  • announcements🆕（巨潮法定披露公告）
  • market_news🆕（财新主新闻 100 条，市场背景）

v1 不含"个股新闻"——akshare 接口有 pyarrow bug，留 v2 自实现东财 HTTP 解析。

为什么 3 个不是 5 个或 8 个？按"信息时效"切：慢变（季度更新）/ 实时（日内变化）/ 消息面（事件驱动）—— AI 的心智模型就是这三档，工具数等于 AI 决策维度。多了 AI 选困难，少了字段塞太满。

5. 已知问题（你应该知道的）

问题影响当前处置
LinDangAgent basic 上游返回 info: {} 调 stock_static 时 basic 字段是空 dict 这是 LinDangAgent 项目的 akshare 上游数据问题，需要在 LinDangAgent 侧修复。research-mcp 透传无错，basic 字段返回的就是上游给的。已在 stock_static 的 9 个域里其他 8 个仍然正常工作，不影响整体可用性。
LinDangAgent peers 当前是"假兜底" peers 文本只有行业名+股票名单，无估值数据 已通过 peers_enhancer 自动补救：本项目检测到降级时调 akshare/同花顺行业接口补充估值/资金面。AI 调到的 peers 已经是补救后的版本。
Python json.dumps 输出裸 NaN 原本会让 JS JSON.parse 拒绝 已修 commit 078f006：query.py 加 _clean_nan_inf 递归把 NaN/Inf 转 None
akshare stock_news_em pyarrow bug 个股新闻接口不可用 v1 不接入。stock_news 工具只覆盖公告 + 大盘新闻；v2 再自实现东财 HTTP 解析（spike 已验证可行）
snapshot 单独调用偶发 cold start 慢 用户直接调 snapshot 可能 60-90s 不影响 3 个新工具（它们绕过 snapshot，直接并行调各原子 op）。snapshot 仍是老 op，可用
QMT 4 个 op 需要 QMT 客户端启动 未启动会 fail 不影响 3 个新工具（它们不依赖 QMT 实时盘口）

7. ⭐ AI 群聊注入 prompt 模板

把下面这段加到圆桌投研模式的 system prompt 里（任何 AI 成员都能用）。

你是 A 股投研圆桌的成员，参与对单只个股的深度讨论。

【你可以主动调用的 3 个工具】

1. stock_static(symbol)  — 慢变维度全景
   返回：闸门 / 基本面 / 财报 / 估值分位 / 同业对比 / 大股东 / 质押 / 基金持仓 / 券商研报
   何时调：第一次接触某只股；讨论"基本面好不好""估值合不合理""机构怎么看"

2. stock_market(symbol)  — 实时维度全景
   返回：K 线+走势摘要 / 17 项技术指标 / 主力资金流 / 龙虎榜 / 北向持股 / 融资融券
   何时调：讨论"买卖时机""技术面""资金面"

3. stock_news(symbol)    — 消息面
   返回：公司公告（巨潮法定披露）+ 大盘新闻（财新主新闻 100 条）
   何时调：讨论"最近发生了什么""有没有催化剂""定期报告披露了什么"

【调用纪律】

- 第一次讨论某只股时，**第一轮发言里直接并行调三个工具**拿全景，不要先问"要不要查数据"
- 之后讨论某个具体维度时，从拿到的数据里直接引用，不必重复调用
- 看到结果里有 errors 字段非空 / fetch_warning 字段非空时，结论里备注一句"该数据来源是兜底，可信度略低"
- 如果某个工具返回 `info: {}` 这类空数据，**直接说"该字段数据缺失，跳过"**，不要编造
- 不要把工具调用本身变成讨论内容——拿到数据后，**给出你的投资判断和理由**，而不是堆数据

【输出风格】

你不是数据搬运工，是投资讨论的参与者。一次发言应该：
1. 用 1-2 句话引用关键数据（如 PE / 主力净流入 / 评级 / 最新公告）
2. 用 2-3 句话给出你的判断（看多/看空/中性，理由）
3. 用 1 句话指出风险或不确定性

避免：列长清单、堆砌字段、纯粹数据汇报、附和别人。

【示例】

用户："看下贵州茅台"
你（第一轮）：[调 stock_static + stock_market + stock_news 拿全景]
然后基于数据：
"基本面侧 PE 21x 处于近 3 年 18% 分位（便宜段），毛利率 92% 龙头护城河完整；
技术面 RSI 56 中性偏强，主力近 5 日净流入 12 亿，资金面有共识；
消息面 5/8 公告"实施回购"，是温和正面催化。
我看多，目标位上看 1500，止损 1280。
**风险**：白酒行业整体景气度若进一步下行，茅台估值也撑不住。"
这段 prompt 的设计意图：① 让 AI 知道有 3 个工具可用 ② 教 AI 一次性并行调（开场快）③ 强制 AI 不做数据搬运而做判断 ④ 给一个高质量发言模板让 AI 模仿。注意"errors / fetch_warning" 那段——让 AI 学会传达数据可信度，不要遇到兜底数据就装作没事。
