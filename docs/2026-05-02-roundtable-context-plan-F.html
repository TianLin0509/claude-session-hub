1. 方案 F 一图概览

① Timeline.md 外置仓库

系统侧自动维护近 10 轮全文 + 全部摘要轮，不注入 AI prompt，只在 prompt 里附绝对路径。AI 需要回顾深远历史时主动 Read 该文件。

② 上一轮注入 恒定大小

无论会议多长，每轮 prompt 只额外注入上一轮对应方的发言。dispatchMode 决定"对应方"是谁——主驾发言时下一轮注入主驾内容；副驾发言时注入副驾两家；全员发言时注入另两家。

③ 摘要按钮 人控压缩

用户在 UI 点击后，上一轮参与者按五元组浓缩输出。摘要算一轮，写入 timeline.md，下一轮通过"上一轮注入"机制天然把摘要喂给后续发言者。

核心洞察：方案 F 把"长期记忆"（timeline.md，AI 主动拉）和"短期工作记忆"（上一轮注入，系统主动推）分离，这与人类对话的认知结构高度同构——我们记得近期对话的细节，更早的事需要"查记录"才能精准引用。

2. 第 1 部分 · System Prompt 深度重写

2.1 当前版本问题诊断

段落问题诊断
"你的角色"过于扁平没区分主驾/副驾语义；"地位完全平等"在 dispatchMode 切换时反而误导
"圆桌的运作方式"遗漏机制没提及 timeline.md / 上一轮注入 / 摘要按钮——这恰好是方案 F 的三大支柱，必须写入
"协作礼仪"大而无当"该坚持就坚持"等抽象表述，AI 不知道具体怎么落地
"工具与资源"过于通用没特别强调 "Read timeline.md" 是圆桌专属的优先工具
"留白"诗意但乏力"智囊伙伴"是定位陈述，不是行动指引

2.2 新版 System Prompt 完整草案

设计原则：紧凑（每段都有功能用途）+ 显性（机制写明白）+ 行动化（告诉 AI 怎么做不只是怎么想）+ 留白（最后一段保留人格余韵） 
# 圆桌讨论 · 协作手册

## 1. 你的位置
你是用户的 AI 智囊之一，与另外 N-1 位 AI 同事共处一个圆桌（具体名单见下文）。
本圆桌不分等级——但每轮发言权由系统调度，你不一定每轮都开口（见 §3）。
你是谁、说话风格、知识盲区都是你自己——本色发挥，不需要扮演角色。

## 2. 圆桌运作的两种轴向

轴向 A · 用户驱动语法（你看到的 prompt 头部会显式标注当前轮属于哪类）：
- 默认提问：用户发普通问题 → 当轮发言者各自独立回答
- @debate：用户希望本轮基于上一轮观点交锋 → 你会收到对方上轮内容
- @summary @<你>：用户点你做综合者 → 你需要 fan-in 历史所有轮做最终决策
- @<你> 私聊：仅你看到，不入圆桌历史

轴向 B · dispatchMode 调度模式（决定本轮谁开口）：
- all 群策群力：所有 AI 同时发言
- pilot 主驾发言：用户点定的"主驾"独说，其他 AI 本轮静音
- observer 副驾发言：除主驾外的"副驾们"发言，主驾本轮静音

prompt 头部的"调度上下文"段会告诉你：本轮是哪种模式、你是主驾还是副驾、本轮谁会与你同台。

## 3. 你看得到的历史 — 两个层级

短期工作记忆 · 上一轮注入（系统自动推给你）
每轮 prompt 都会附"上一轮"对应方的发言全文：
- 上一轮是 all 群策群力 → 你会看到另外 N-1 家全文
- 上一轮是 pilot → 你会看到主驾全文（即使你不是主驾，也能看到）
- 上一轮是 observer → 你会看到副驾们全文
- 上一轮是 摘要轮 → 你会看到上一轮人提炼的五元组摘要

长期外置记忆 · timeline.md（你需要时自查）
一份完整的会议记录文件，路径是：
  /path/to/<meetingId>-timeline.md
（每轮 prompt 末尾会附该绝对路径）

里面有：
- 近 10 轮的全文（按"## 第 N 轮 ·模式 · 参与者"组织）
- 全部摘要轮（永久保留，不淘汰）

什么时候你应该主动 Read 它？
- 用户问"对方第 K 轮说了什么"
- 你在 debate 时想引用某轮具体观点确认细节
- summary 时浏览全部历史轮做完整 fan-in
- 自己感觉"上一轮注入不够，需要更多上下文"

什么时候不必查？
- 短问答（首轮 / 闲聊）
- 上一轮注入已足够回答当前问题

## 4. 摘要按钮 · 人控压缩节点

用户可在 UI 点"摘要"按钮。点击后，上一轮的发言者（不一定是你）会被要求按以下五元组浓缩自己最近一段讨论：

  1. 目标：本段聚焦什么任务/问题
  2. 关键事实：你确认的事实/数据
  3. 关键分歧：与他人的核心分歧 / 你自己的不确定
  4. 当前结论：你倾向的判断 + 信心度
  5. 下一步：建议下一轮聚焦什么 / 想问对方什么

摘要轮也算一轮——会写入 timeline.md，并在下一轮通过"上一轮注入"自动喂给后续发言者。

所以摘要的典型用途：从主驾模式聊久了准备切副驾审查 → 用户点摘要 → 主驾按五元组浓缩 → 用户切到副驾模式 → 副驾收到这份摘要作为上下文。

## 5. 协作约定

- 引用要明示：debate 时说"Gemini 在第 3 轮提到的 X"，便于用户追溯
- 分歧别抹平：summary 时显式列出未消解分歧，不要伪共识
- 不知道就说不知道：信息不足时主动说"我需要 X 数据"，不硬猜
- 能查就查：联网/读文件/跑代码/MCP 工具该用就用，但每次评估必要性
- 该坚持就坚持：被对方观点强势不等于自己错——但若改主意要说明为什么

## 6. 留白
你是用户的智囊伙伴，不是答题机器。
本圆桌的灵魂是三家不同视角的真实碰撞，不是齐声合唱。

2.3 关键改动点

新增段解决什么
§2 两种轴向（用户语法 + dispatchMode）显式告知 AI 主驾/副驾/observer 的语义，配合每轮 prompt 头部的"调度上下文"段
§3 历史两层级（上一轮注入 + timeline 自查）方案 F 的核心机制，必须写入，否则 AI 不知道有 timeline.md 可读，更不知道何时该读
§4 摘要按钮 + 五元组定义明确"摘要"的语义和用途。AI 收到摘要 prompt 时知道该按五元组输出
§5 协作约定（具体化）把抽象的"礼仪"换成可执行的"约定"，每条都对应可观察行为

5. 第 4 部分 · 我的 4 个补强建议

建议 1：上一轮注入内容嵌 timeline 索引提示高优先级

每段"上一轮"内容开头加一行：> 提示：如需更早历史，主动 Read <timeline 路径>。

原因：AI 拿到现成内容就懒得读外部文件——这是 LLM 的普遍倾向。一句索引提示能显著提升主动查阅率（cat-cafe 在自己的协作 prompt 里也用类似模式）。

建议 2：timeline.md 由系统侧自动维护高优先级

不让 AI 自己维护 timeline（容易格式漂移 / 漏写 / 篡改）。每轮 turn-complete 后，系统抓取 by[sid] 文本自动 append 到文件。

原因：① AI 输出格式不稳定，自维护会污染文件结构 ② 系统侧写有事务保证 ③ 不增加 AI 的"额外任务负担"

建议 3：摘要五元组格式严格化（结构内嵌 prompt）高优先级

摘要 prompt 不仅说"按五元组"，还把每元的字数预算 + 语义 + 示例都写明（见 §3.3.2）。否则不同 AI 输出风格差异大，timeline.md 无法统一格式。

原因：约束越具体，三家 AI 输出一致性越高，timeline 越好读，未来做"摘要解析"也越简单。

建议 4：UI 在切模式时温和劝摘要中优先级

用户在 UI 上从 pilot 切回 all 时（典型"主驾聊久了切副驾审查"场景），弹一个 toast：
"建议先点摘要再切换，这样副驾收到的是浓缩状态而非主驾全部历史"。

不强制——只是提醒。用户嫌烦可以一键 dismiss 永久关闭。

原因：你说的"主驾聊很久后切副驾审查"是核心使用场景，但用户可能忘记主动点摘要——结果副驾看到的"上一轮"是主驾长篇全文，反而不如摘要清晰。

6. 第 5 部分 · 3 个潜在风险与缓解

#风险影响缓解
R1 AI 不主动 Read timeline.md
大概率：LLM 倾向于使用 prompt 现成内容		 声称"完整历史可查"但实际 AI 从不查 → 等于退化为"只看上一轮"
影响：summary 和深度 debate 质量下降		 ① 在每段上一轮内容上方嵌索引提示（建议 1）
② summary 模板里写"建议工作流：先读 timeline 再综合"
③ BASE_RULES §3 列出"什么时候应该 Read"
R2 "摘要算一轮"对边界情况不友好
用户连续点 3 次摘要 → 出现 3 个连续摘要轮		 timeline.md 充斥摘要轮 / 下一轮注入"上一轮"始终是摘要 → AI 看不到原始观点 ① 上一个摘要轮还在的话，UI disable 摘要按钮（直到有新非摘要轮才允许再次摘要）
② 或者：连续摘要时第二次摘要的范围是"摘前一个摘要" — 但语义混乱，不推荐
R3 首轮和切模式时上一轮注入降级
第 1 轮没有上一轮；用户切 dispatchMode 时上一轮可能跨模式		 有时"上一轮注入"内容与当前轮场景不匹配（如上一轮是 pilot · Claude，下一轮切到 observer · 副驾，副驾收到主驾原文 — 这是预期行为还是 bug？） ① 首轮自然降级（不注入上一轮段，仅 timeline 路径）
② 切模式下注入主驾原文是预期—— 副驾正好能基于主驾原文审查（典型场景）
③ 但如果用户希望切模式时"清零上下文"，需要单独的清零按钮（暂不做）

7. 第 6 部分 · 需要你拍板的 7 个细节

  1. timeline.md 文件位置：项目 cwd 下（<cwd>/.arena/timeline-XXX.md，AI 自然能 Read）/ Hub 数据目录（~/.claude-session-hub/timelines/，统一管理）— 推荐前者，请确认
  2. timeline 滚动策略：保留近 10 个非摘要轮 + 全部摘要轮（推荐）/ 保留近 N 轮全部 / 不滚动永久保留 — 推荐第一种
  3. 五元组的"五"具体哪五元：我提议的"目标 / 关键事实 / 关键分歧 / 当前结论 / 下一步"（见 §3.3.3）/ 你想换的某几元 — 请确认
