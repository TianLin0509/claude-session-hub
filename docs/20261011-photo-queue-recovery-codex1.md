# 拍图队列被旧回答阻塞：2026-10-11

用户现象：镜腿触发拍照，手机显示加入队列，拍图助理没有运行。

## 已核实的根因

22:36:13 的照片 `3b671321-8319-48ab-8b2e-d08c4a3a9bba` 已由生产电脑接收，状态为 queued。队首 `400cee7c-6d3f-4862-9bbb-f5b5223e501b` 仍为 waiting；其 Claude 原生记录实际在 20:05:50 已写入最终回答，手机未得到对应回答，后续三张旧照片及本张被阻塞。

Claude 2.1.296 读取图片后插入 `type=user, isMeta=true, turnCompanion=true` 的尺寸说明。10 月 3 日引入的请求关联读取逻辑（`7e93c95a1`）把它当成用户新提问，清空 clientSubmissionId。由于 Claude 接收回执没有另一个可用 turnId，手机通道不能认领最终回答。冷启动反向读取也会错误地停在该尺寸说明处。

这属于电脑端原生记录解析问题；本次照片的上传、镜腿触发正常。此前 Android 发布链路使用隔离 Codex，不能覆盖 Claude 图片伴随消息格式，新增回归专门覆盖该格式。

## 修复与验证

- 实时解析和冷启动反向扫描共用用户提问判定：排除侧链、meta、turnCompanion 与工具结果。
- 真正的后续电脑提问仍清空旧请求编号，防止把无关回答发给旧照片。
- 回归先失败后通过；覆盖完整读取、增量读取、超过 1 MiB 的冷启动、真人新提问、队首旧答案核对后只派发一次下一张照片。
- 只读生产原生记录重放：旧代码得到 null，新代码得到正确旧照片编号；原文件哈希不变。证据在 `artifacts/20261011-photo-queue-native-proof-codex1.json`。
- 不删除排队照片，不手工改生产队列，不自动重发已提交照片。

修复模块需要生产 Hub 重新加载后生效；本任务不关闭或重启用户的生产 Hub。手机 1.2.11 无需升级。生产旧任务实际解除、排队照片逐个答复和真机朗读仍需在用户重开 Hub 后核实。
