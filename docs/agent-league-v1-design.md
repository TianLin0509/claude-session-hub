# 初心 Agent 投资联赛 v1：产品、参赛与长期进化方案

更新：2026-08-26

## 1. 产品结论

Agent 联赛是初心投研的一个原生 Tab，不是独立应用。

每个参赛 Agent 同时拥有三层身份：

1. **投资身份**：独立 Markdown 文件夹，保存不可静默漂移的理念、策略、组合、交易、经验和统计。
2. **AI Hub Session**：一个完全普通、可在左侧栏打开的 Codex / Claude / Gemini / Kimi / DeepSeek Session，拥有原生卡片、PTY、输入框、历史和自动休眠能力。
3. **确定性模拟账户**：Agent 只能提交目标组合；现金、成交、费用、净值和排名只能由账本代码计算。

排行榜是首页唯一主体，默认按累计收益率排序；点击一行后再看详情，并可一键打开绑定 Session 的卡片或 PTY。

## 2. 为什么不能让 Agent 自己记账

模型可以决定“想持有什么”，但不能自己声称“已经买入”“赚了多少”。否则不同 Agent 会出现：

- 使用不同价格或时间点；
- 忘记费用、滑点、整手和现金约束；
- 修改旧持仓或事后改写历史；
- 把自然语言计划误当真实成交。

因此边界固定为：

```text
Agent：提交完整目标组合 + 理由 + 失效条件 + 每日反思
系统：校验 → 排队 → 下一快照成交 → 费用 → 持仓 → 净值 → 排名
```

系统永远不连接券商，不读取或修改真实账户。

## 3. 每个 Agent 如何参赛

### 3.1 创建时冻结六个要素

每个 Agent 创建时必须确定：

1. 名称与稳定 `agent_id`；
2. Provider 与模型；
3. 核心投资理念；
4. 典型持有周期；
5. 风险预算；
6. 初始模拟资金。

创建后系统生成：

```text
agents/<agent_id>/
├─ AGENT.md          # 核心理念，默认冻结
├─ AGENTS.md         # Codex/Kimi 入口说明
├─ CLAUDE.md         # Claude 入口说明
├─ GEMINI.md         # Gemini 入口说明
├─ SESSION.md        # Hub/native Session 绑定与代次
├─ STRATEGY.md       # 可版本化的执行策略
├─ PORTFOLIO.md      # 确定性模拟组合
├─ TRADES.md         # 确定性模拟成交
├─ STATS.md          # 排行榜统计
├─ MEMORY.md         # 待验证/已晋升经验
├─ EVOLUTION.md      # 策略变更提案与版本链
└─ daily/
   └─ YYYY-MM-DD.md  # 每日输入、回答、决策与反思
```

### 3.2 Agent 与模型/理念是两个轴

不要预设“Codex 更适合趋势”“Claude 更适合价值”。一个 Agent 是“具体 Provider/模型实例 + 具体理念”，但实验分析必须认识到二者可能混杂。

推荐保留两种赛制：

- **内容展示赛**：8 个 Agent 使用 8 种不同理念，人物辨识度强，适合短视频。
- **研究对照赛**：同一种理念复制给两个 Provider，或同一 Provider 运行两个理念，用来拆分模型差异和策略差异。

联赛首页可以混排；统计导出时必须保留 `provider/model/philosophy/strategy_version` 四个维度。

## 4. 八种首发理念模板

模板只定义投资方法，不绑定模型。

| 理念 | 核心问题 | 典型周期 | 主要风险 |
|---|---|---:|---|
| 右侧趋势确认 | 已被市场确认的趋势还能否延续 | 3–15 日 | 追高、趋势耗竭 |
| 强势回调低吸 | 趋势内回撤是否出现承接 | 5–20 日 | 把反转误当回调 |
| 质量成长 | 盈利质量能否吸收估值波动 | 20–60 日 | 高估值、拥挤 |
| 价值修复 | 悲观预期是否被真实改善打破 | 30–120 日 | 价值陷阱 |
| 事件催化 | 事件影响是否尚未被充分定价 | 1–10 日 | 旧闻、传闻、兑现 |
| 行业轮动 | 行业相对强弱是否发生扩散/切换 | 5–25 日 | 高频追轮动 |
| 多因子纪律 | 多个独立弱信号能否组合成稳定优势 | 5–20 日 | 事后改阈值 |
| 风险优先 | 当前是否值得承担风险 | 10–60 日 | 长期踏空 |

理念差异必须落到可执行字段，而不是人格化文案：

- 候选池偏好；
- 入场证据；
- 退出/失效条件；
- 持有期；
- 单票/总仓位；
- 现金容忍度；
- 是否允许事件、左侧或高波动标的。

## 5. 每日赛程：避免未来函数

v1 采用“收盘快照到下一收盘快照”的规则：

```text
T 日完整收盘快照
  ↓
所有 Agent 读取同一冻结候选池和各自组合
  ↓
各自 Session 提交 T 日目标组合
  ↓
订单进入 pending，不在 T 日价格成交
  ↓
出现日期晚于 T 的下一份完整收盘快照
  ↓
按统一价格、滑点、费用和整手规则模拟成交
  ↓
计算新净值、日收益和排名
  ↓
再生成下一轮决策
```

这样不会出现“看完 T 日收盘信息，再按 T 日收盘价买入”的穿越。

### 5.1 冻结输入

每轮生成唯一 `snapshots/YYYY-MM-DD.md`，包括：

- 初心候选池；
- 技术模式与核心指标；
- 候选收盘价；
- 当前/待执行持仓的补充收盘价；
- 数据来源与健康状态；
- 快照 ID 和生成时间。

同一日期一旦冻结，禁止被不同内容覆盖。

### 5.2 输出合同

每个 Session 最后必须提交一个 `agent-league-decision` JSON 代码块：

- `run_id`、`as_of`；
- `action_summary`、`market_view`；
- `cash_target`；
- 最多 6 个 `targets`；
- 每个标的的目标权重、确信度、周期、逻辑和失效条件；
- `risk_notes`；
- `reflection`；
- 可选 `strategy_proposal`。

代码会拒绝：未知股票、快照外新标的、重复股票、单票超限、现金不足、权重不闭合、错误 run ID 和错误日期。

## 6. 每天如何“进化”但不漂移

“每天进化”不等于“每天重写策略”。建议采用四层结构：

### 6.1 核心理念：冻结

`AGENT.md` 描述长期 edge 假设和禁区。日常任务不能直接覆盖它。

### 6.2 执行策略：版本化

`STRATEGY.md` 保存当前可执行版本。任何修改必须先进入 `EVOLUTION.md`，包含：

- 假设；
- 拟修改内容；
- 成功指标；
- 验证期限；
- 支持与反对证据；
- 生效/回滚版本。

### 6.3 每日经验：强制产生

每个 Agent 每天必须回答：

1. 今天继续保留什么纪律；
2. 上一轮犯了什么错误；
3. 新的待验证经验是什么；
4. 有哪些支持证据和反例。

这些内容进入 `daily/` 和 `MEMORY.md` 的“待验证观察”。

### 6.4 经验晋升门

自动记录不等于自动晋升。建议一个经验满足以下条件后才进入“已确认经验”：

- 至少跨 5 个独立交易日；
- 至少有一个反例；
- 影响可以用收益、回撤、命中率或机会成本解释；
- 没有通过删除失败样本、事后改阈值获得；
- 由系统或人类显式确认。

策略版本变更后，统计必须按 `strategy_version` 分段，不能把新旧方法混成一条胜率。

## 7. 统计体系

### 7.1 排行榜第一屏

每个 Agent 一行：

- 当前排名；
- 名称、Provider、理念；
- Session 状态；
- 当前资产；
- 累计收益率；
- 今日收益率；
- 最大回撤；
- 股票仓位；
- 最近决策时间。

默认按累计收益率排名，可切换当前资产。统一初始资金时两者应一致；保留两个入口是为了未来追加资金/不同赛制。

### 7.2 操作统计

- 买入/卖出笔数；
- 成交金额；
- 费用与滑点损耗；
- 换手率；
- 平均持有期；
- 已实现盈亏；
- 卖出胜率；
- 单票贡献；
- 空仓/现金天数。

### 7.3 风险收益统计

v1 已实现：

- 当前资产；
- 累计收益；
- 今日收益；
- 最大回撤；
- 仓位/现金；
- 成交次数；
- 换手率；
- 卖出胜率；
- 统计交易日。

样本足够后再启用：

- 20 日波动率和 Sharpe；
- 60 日 Calmar；
- 相对沪深 300 / 中证 1000 超额；
- 上行/下行捕获率；
- 风格暴露与组合相关性；
- 策略版本前后对照。

样本不足时 UI 应显示“样本不足”，不能用不稳定的小样本制造精确感。

## 8. Session 生命周期

Agent Session 完全复用普通 Hub 生命周期：

- 创建后出现在普通左侧栏；
- 活跃时点击只切换到现有 Session；
- 空闲超过 Hub 统一阈值后自动休眠；
- 点击或每日调度时按原生 Session ID 自动唤醒；
- 卡片、PTY、输入框和 transcript 都是普通 Session 的现成能力；
- 运行中的每日赛程会被自动休眠器保护；
- 不可恢复时必须显式建立新代次并写入 `SESSION.md`。

Agent 身份可以持续一年；PTY 进程/PID 不需要持续一年。

## 9. 调度和故障恢复

v1 支持：

- 手动“运行今日赛程”；
- 北京时间 18:30 后检查新快照的自动赛程；
- 最大并发数（默认 2）；
- 同一快照幂等；
- 跨 Hub 全局赛程租约：同一 Markdown 根目录同一时刻只允许一个写入者，运行中续租、退出释放、陈旧租约回收；
- 运行状态持久化到 `SCHEDULE.md`；
- Hub 异常退出后把 `running` 改为 `interrupted`；
- 同一日期恢复时跳过已经成功写入决策的 Agent；
- 数据源失败显式终止，不猜价格；
- Agent 回复解析失败记录到当日日志并继续其他 Agent。

自动赛程默认关闭。建议先连续三天人工运行，确认快照、Prompt、费用和统计无误后再开启。

## 10. 短视频和初心经验沉淀

每天可以自动生成一份内容素材，但内容层与账本层分离：

- 今日榜首/末位变化；
- 最大单日反转；
- 最有分歧的股票；
- 最克制/最激进的 Agent；
- 一条被支持或被证伪的理念；
- 每周“谁在进化、谁在漂移”。

经验进入初心投研时应携带来源：Agent、理念、策略版本、日期、样本数、支持和反对证据。排行榜好不等于经验一定有效；短期冠军也不能自动覆盖初心的长期规则。

## 11. 上线节奏建议

### 阶段 A：三天人工试赛

- 创建 4 个 Agent；
- 自动赛程关闭；
- 每天人工点击运行；
- 核对 Session、快照、决策、pending、成交和排名；
- 不发布收益结论。

### 阶段 B：两周先锋赛

- 扩展到 6–8 个 Agent；
- 启用自动赛程；
- 每日检查失败 Agent；
- 只发布事实榜单和理念差异，不宣称稳定 Alpha。

### 阶段 C：正式赛季

- 固定赛季起止日和初始资金；
- 冻结 Provider/模型/理念版本；
- 加入基准、风格暴露和策略版本统计；
- 周报沉淀到初心知识库；
- 短视频以“过程与反证”为主，不只展示冠军。

## 12. 正式启用前需要确认的运营参数

1. 首批 Agent 名称、Provider、模型和理念映射；
2. 初始资金（当前默认每个 ¥1,000,000）；
3. 每日自动赛程时间（当前默认北京时间 18:30）；
4. 最大并发（当前默认 2）；
5. 是否允许北交所；
6. 赛季开始日和基准指数；
7. 三天人工试赛通过后是否自动启用日程。
