二、审计中实际发现并修复的高优先级问题

跨 key overview cache 乱序覆盖

旧工作区扫描晚完成会污染新 key。改为 request identity guard，并增加慢 A / 快 B 的确定性竞态测试。

跨 Hub 审阅账本丢决定

单进程锁不足以保护两个 Hub。加入跨进程文件锁、blob+hunk 绑定、review 前后 blob 校验与 captured commit diff 复核。

Checkpoint 证据 TOCTOU

旧实现把实时工作树决定包装成已捕获 tree 的证据。现在仅保留同时匹配 checkpoint blob 与 hunk 内容哈希的审阅。

健康检查畸形重定向导致未捕获异常

Location URL 解析移入受控 reject；跨 origin redirect 不携带 bearer token。

搜索缓存解压与高熵索引爆内存

增加 shard 解压上限、4MB/source、64K/doc、key/posting 总预算、短读保护、tombstone 回收和 60 次高熵替换测试；在根因完成取证前，生产默认关闭 Worker。

Search worker 退出后 IPC 永久 pending

修正 exit/failure 顺序，非零退出立即 reject 全部 pending，并允许后续按需重建 worker。

PTY no-onExit 导致永久无法退出

新增 15 秒 deadline；窗口先拦截 close，失败保留/重建窗口；部分完成与迟到 exit 转 dormant，不误删 Session/群聊成员。

cleanShutdown 假阳性

等待 worker，汇总 usage/meeting/session flush 后最后写 clean flag；lifecycle journal 同步继承 cleanup 结果。

Modal/快捷键跨层穿透

统一 modal-layer guard；处理隐藏祖先、excluded root、Search/Preview/Operations/Config/Cmd+K；Esc 只关闭顶层。

驾驶舱被 terminal innerHTML 清除

operations modal 纳入 preserve 节点；Home→Session→Home 后可再次打开，E2E 已覆盖。

Global Search 关闭 RAF 空指针

清空共享 focus 状态前捕获局部 focusTarget，避免下一帧执行 null.focus。

Spirit 测试与审计静默失败

改用临时 fake registry；Python 15 秒 timeout；prepare/validate 审计落盘失败返回 isError，不能伪装成功。

四、生产现场：代码门通过，但仍有一个开放风险

生产主进程内存仍偏高

8 月 25 日仅通过操作系统只读采样：PID 62860 Responding=True，private≈2139MB、working set≈510MB。8 月 24 日更深一层的旧实例采样曾观察到 main heap≈2956MB；本轮没有连接生产 CDP，因此不把当前 private memory 等同于 JS heap。该风险尚未关闭。

历史突然停止仍缺最终根因

生产 PID 61444 与 7412 的 lifecycle heartbeat 曾突然停止，journal 没来得及写 process-exit；Windows Application/WER 同时段也没有匹配事件。证据可以排除普通 JS exception，但暂时不能区分 native fail-fast、OOM 或外部终止。

建议下一步：保持生产 Hub 不动，在用户明确允许后，对高内存实例做一次只读 heap/diagnostic 取证，或用相同数据规模在隔离 Hub 复现；不要为了验证本提交直接重启生产进程。当前生产进程启动于 8 月 24 日 10:23，本轮从未重启或 CDP 控制，不会自动获得隔离分支代码。

五、剩余 P2 / 后续观察项

Checkpoint 移除源 worktree 后恢复OPEN P2manifest 仍以原 repoRoot 为恢复入口；linked worktree 被正常移除后，common Git object/ref 仍在，但 UI 可能报 invalid_repo_root。
裸 codex 行编辑OPEN P2Host shell 下使用方向键/Home/End 编辑命令会放弃受管启动跟踪，需进一步做 ConPTY 行编辑状态机。
长期 terminal listener 数量OPEN P2每个保留 live terminal 仍有 resize/click/observer，只有 suspend/close 才释放；需要结合高内存实例专项取证。
Workbench stale snapshot 语义OPEN P2刷新失败会在状态栏报错但保留旧 snapshot；建议后续在返回结构中显式标 stale。
Lifecycle journal 自身健康OPEN P2写失败不阻断启动是正确策略，但生产 UI 尚未显式展示 journal unavailable。
